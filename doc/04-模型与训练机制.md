## 1. 模型架构（`nanochat/gpt.py`）

### 1.1 总体特性

GPT 是一个 decoder-only Transformer，模块 docstring 列出关键特性（`nanochat/gpt.py` 顶部）：

- **旋转位置编码**（rotary），无单独的可学习位置 embedding。注意源码按**反向角度**（`-theta`，textbook 转置约定）旋转，为 checkpoint 兼容保留；
- **QK norm**（query/key 各做 rms_norm）；
- **token embedding 与 lm_head 权重不共享**（untied）；
- **relu² 激活**（`F.relu(x).square()`，`nanochat/gpt.py#MLP`）；
- embedding 后做一次 norm；
- **rmsnorm 无可学习参数**（`nanochat/gpt.py#norm`）；
- Linear 层无 bias；
- 支持 **GQA**（`n_kv_head <= n_head`，默认相等即无 GQA）；
- 集成 **Flash Attention 3**。

还有一批**不在上面清单里、但已经实现**的非标准结构，见 §1.3。

### 1.2 前向流程（`nanochat/gpt.py#GPT.forward`）

```
idx (B,T)
 │
 ├─ rotary 按 kv_cache 位置偏移取 cos/sin，并 assert dtype == COMPUTE_DTYPE
 ├─ x = wte(idx) → cast 到 COMPUTE_DTYPE → norm(x)
 ├─ Smear: 把上一 token 的 embedding 混入当前位
 │     gate = smear_lambda * sigmoid(smear_gate(x[:, :, :24]))
 │     x[1:] += gate * x[:-1]                     # 训练 / prefill
 │     x += gate * kv_cache.prev_embedding        # decode 单 token
 ├─ x0 = x  # 保存 smear+norm 之后的初始 embedding 给 x0 残差（不是 wte 的原始输出）
 ├─ for i, block in transformer.h:
 │     x = resid_lambdas[i]*x + x0_lambdas[i]*x0  # 残差缩放 + x0 回混
 │     ve = value_embeds[str(i)](idx)  (若有)
 │     x = block(x, ve, cos_sin, window_sizes[i], kv_cache)
 │     if i == n_layer//2: x_backout = x          # 记录中层残差
 ├─ x = x - backout_lambda * x_backout            # 减去中层低级特征
 ├─ x = norm(x)
 ├─ logits = lm_head(x)[..., :vocab_size].float()
 ├─ logits = 15 * tanh(logits/15)                 # logit softcap
 └─ targets 给定 → cross_entropy(ignore_index=-1, reduction=loss_reduction)
    否则返回 logits
```

`loss_reduction` 是**对外开放的关键旋钮**：bpb 评估与 RL 的 PG 目标都传 `'none'` 拿逐 token loss。

### 1.3 非标准结构的细节

1. **Smear**（`nanochat/gpt.py#GPT.__init__` 里的 `smear_gate`/`smear_lambda`）：用前一个 token 的 embedding 做廉价 bigram 信息注入。`smear_gate` 是 `Linear(24, 1)`，**只看 embedding 的前 24 维**；门控是 `sigmoid` 乘上可学习标量 `smear_lambda`。

   > 训练与推理路径不同，必须对齐：训练时用整段切片一次性算；推理 prefill 时走同样逻辑；decode（T=1）时没有「前一个 token」在本次 batch 里，于是从 `kv_cache.prev_embedding` 读，并把当前 embedding 写回去。**这是 KV cache 里除了 K/V 之外唯一的额外状态**，也是 `KVCache.prefill` 要展开 `prev_embedding` 的原因——batch=1 prefill 完成后把所有缓存 `expand().clone()` 成 `num_samples` 份，这就是 Engine 多样本并行采样的入口。

2. **resid_lambdas / x0_lambdas**：每层可学习的残差缩放与「初始 embedding 回混」系数。注意回混的 `x0` 是 **smear 之后、norm 之后的 embedding**（源码注释自称 "initial normalized embedding"），不是 `wte` 的原始输出。初始化分层（`nanochat/gpt.py#GPT.init_weights`）：
   - `resid_lambdas[i] = 1.15 - 0.10 * i/(n_layer-1)`（浅层残差更强）
   - `x0_lambdas[i] = 0.20 - 0.15 * i/(n_layer-1)`（浅层回混更多）
   - `backout_lambda` 初始化为常数 **0.2**，`smear_lambda` 初始化为 **0**（先关闭再学）。

3. **Value Embeddings (ResFormer)**：交替层有 value embedding，`has_ve` 判定为 `layer_idx % 2 == (n_layer - 1) % 2`（**保证最后一层一定有**）。attention 里用 `ve_gate` 控制每个 kv head 把 ve 混进 v，门控范围 0~3：
   ```
   gate = 3 * sigmoid(ve_gate(x[..., :12]))    # ve_gate_channels = 12
   v = v + gate.unsqueeze(-1) * ve
   ```

4. **Backout**：在 logit 投影前减去 `n_layer//2` 处的残差，去除低级特征。

5. **Logit softcap**：`15 * tanh(logits/15)`，平滑限制 logits 范围。**先 `.float()` 再做 tanh**，因为 bf16 下 tanh 与除法会掉精度。

6. **词表 padding**：`GPT.__init__` 有 `pad_vocab_size_to=64`，`lm_head` 输出维度是**向上取整到 64 的倍数**，forward 里再切回 `vocab_size`。目的是让最后的 matmul 维度友好（对齐），代价是 logits 张量稍大。

### 1.4 Attention（`nanochat/gpt.py#CausalSelfAttention`）

```
q = c_q(x)  → (B,T,n_head,head_dim)
k = c_k(x)  → (B,T,n_kv_head,head_dim)
v = c_v(x)  → (B,T,n_kv_head,head_dim)
if ve is not None:
    v = v + gate*ve                               # value residual, gate∈(0,3)
q,k = rotary(q,k);  q,k = norm(q),norm(k)          # QK norm
q *= 1.2;  k *= 1.2                               # 经验性「更尖锐注意力」增益（不是 1/sqrt(d)）
if kv_cache is None:                              # 训练
    y = flash_attn_func(q,k,v, causal=True, window_size=window_size)
else:                                             # 推理
    k_cache, v_cache = kv_cache.get_layer_cache(layer_idx)
    y = flash_attn_with_kvcache(q, k_cache, v_cache, k=k, v=v,
                                cache_seqlens=kv_cache.cache_seqlens, ...)
    if layer_idx == kv_cache.n_layers - 1: kv_cache.advance(T)
y = c_proj(y.contiguous().view(B,T,-1))
```

- 布局是 FA3 原生的 `(B, T, H, D)`，**不需要转置**（SDPA 回退时才在内部转成 `(B,H,T,D)`）。
- `window_size` 是 `(left, right)` 元组：`(-1, 0)` 表示全上下文，`(N, 0)` 表示滑动窗口。
- `q *= 1.2; k *= 1.2` 是一个**经验性的「更尖锐注意力」因子**（源码注释自称 `sharper attention (split scale between Q and K)`，并带 TODO 说要想清楚更好的做法）。
  > ⚠️ 它**不是**把 softmax 的 `1/sqrt(head_dim)` 缩放拆到 Q/K 上——`1.2 × 1.2 = 1.44`，而 `1/sqrt(128) ≈ 0.088`，量级完全不同。（softmax 的 `1/sqrt(d)` 由 attention 内核内部处理，这里是在它之上再乘的一个额外增益。）
- **最后一层负责推进 KV cache 位置**（`advance(T)`）——这是训练/推理一致性的关键约定：`advance` 只在最后一层调用一次，避免每层都推。

### 1.5 滑动窗口（`nanochat/gpt.py#GPT._compute_window_sizes`）

`window_pattern`（默认 `SSSL`）按字符平铺到各层。源码是「先整除、再向上取整到 128 的倍数」两步：

```
long_window  = sequence_len
short_window = -(-long_window // 4 // 128) * 128    # = ceil(floor(seq/4) / 128) * 128
char_to_window = { "L": (long_window, 0),  "S": (short_window, 0) }
window_sizes[i] = char_to_window[pattern[i % len(pattern)]]
window_sizes[-1] = (long_window, 0)                 # 最后一层永远是 L
```

> 注意分组：是 `ceil( floor(seq/4) / 128 ) * 128`，**不是** `ceil(seq/4/128)*128`。对 `seq` 是 512 的倍数的情况两者相同，但别把公式简写成后者。

以 `seq_len=2048` 为例：`-(-2048 // 4 // 128) * 128` → `512 // 128 = 4` → `× 128` = **512**（正好是 1/4 上下文，且已是 128 的倍数）。

> 源码该行的**注释写的是 `2048 -> 768`，与代码实际结果（512）不符**，看起来是从旧公式留下的。读代码时以表达式为准，不要照抄注释。

- 短窗口的作用是降 decode 时的 KV 读取量与 attention 计算量；`S` 层只保留 1/4 上下文。
- **最后一层固定为 L** 是刻意的：全局信息仍能聚合到输出。
- `estimate_flops` / `estimate_decode_flops` / `estimate_prefill_flops` / `kv_read_bytes` **都按每层各自的 window 求和**，所以改 `window_pattern` 会同时改训练 MFU 口径和推理成本估计。

### 1.6 初始化（`nanochat/gpt.py#GPT.init_weights`）

集中在一个函数里完成，便于阅读：

| 参数 | 初始化 |
|------|--------|
| `transformer.wte.weight` | `normal(std=0.8)` |
| `lm_head.weight` | `normal(std=0.001)`（开始接近随机输出） |
| `attn.c_q/c_k/c_v.weight` | `uniform(-s, s)`，`s = sqrt(3)*n_embd^-0.5`（**用 Uniform 而非 Normal 以避免异常值**，乘 `sqrt(3)` 使 std 等价） |
| `attn.c_proj.weight` | zeros |
| `mlp.c_fc.weight` | `uniform(-0.4s, 0.4s)`（额外 0.4 倍缩放） |
| `mlp.c_proj.weight` | zeros |
| `value_embeds[*].weight` | `uniform(-s, s)`（同 c_v） |
| `ve_gate.weight` | `uniform(0, 0.02)`（小正数，门初始略高于中性） |
| `smear_gate.weight` | `uniform(0, 0.02)` |
| `smear_lambda` | zeros |
| `backout_lambda` | `0.2` |
| `resid_lambdas` / `x0_lambdas` | 见 §1.3 第 2 点 |

最后把 `wte` 与 `value_embeds` cast 到 `COMPUTE_DTYPE` 省显存，**例外是 fp16**：`if COMPUTE_DTYPE != torch.float16`，因为 GradScaler 无法 unscale fp16 梯度。

Rotary 的 cos/sin 也在 `init_weights` 里预算（`_precompute_rotary_embeddings`，`base=100000`），device 从 `wte` 权重自动推断。**这是 `build_model` 必须先 `init_weights` 再 `load_state_dict` 的原因**：`cos`/`sin` 在 `GPT.__init__` 里就以 `persistent=False` 注册了 buffer（checkpoint 里本来就没有、strict load 不会因缺失报错），但 `to_empty` 会把它们清成**未初始化的垃圾数据**，必须重跑一次预计算才能用。

> 源码 `init_weights` 的 **docstring 本身已过时**：注释写 `wte std=1.0`、`c_fc std=1/sqrt(n_embd)`，代码实际是 0.8 与 0.4 倍缩放（见上表）。与 §1.5 的 `2048->768` 注释同理：**以代码为准，不要照抄注释**。

### 1.7 朴素生成（`nanochat/gpt.py#GPT.generate`）

无 KV cache、逐 token 全量重算的流式生成，`batch size = 1`，yield 单个 int。主要作**对照基准**：`nanochat/engine.py` 的 `__main__` 会比对它与 `Engine.generate` 的输出是否逐 token 一致。

## 2. 混合优化器（`nanochat/optim.py`）

### 2.1 设计思想

- **矩阵参数**（attn/mlp 的 2D 权重）用 **Muon**（动量 + 正交化）；
- **其余参数**（embedding、lm_head、各类标量）用 **AdamW**（融合内核）；
- 参数分组在 `nanochat/gpt.py#GPT.setup_optimizer` 完成，按 `kind` 字段分派；
- **单机与分布式是同一个类** `MuonAdamW`（`nanochat/optim.py#MuonAdamW`），没有进程组时通信全部跳过。

### 2.2 参数分组（`nanochat/gpt.py#GPT.setup_optimizer`）

函数签名带默认值：`setup_optimizer(unembedding_lr=0.004, embedding_lr=0.2, matrix_lr=0.02, weight_decay=0.0, scalar_lr=0.5)`。分组前有一个 `assert`：所有参数必须被恰好分进某一组，**防止新增参数被静默漏训**。

AdamW 组：

| 组 | LR（`setup_optimizer` 内的表达式，均为**未乘 batch 缩放**的基准值） | betas | weight_decay | eps | 受 `dmodel_lr_scale`（宽度）影响 |
|----|----------------|-------|--------------|-----|--------------------------|
| lm_head | `unembedding_lr = 0.004` | (0.8, 0.96) | 0.01 | 1e-10 | ✅ |
| embedding (wte) | `embedding_lr = 0.2` | (0.8, 0.995) | 0.001 | 1e-10 | ✅ |
| value_embeds | `embedding_lr * 0.5` | (0.8, 0.995) | 0.01 | 1e-10 | ✅ |
| resid_lambdas | `scalar_lr * 0.01`（基准 0.005） | (0.8, 0.95) | 0.05 | 1e-10 | ❌ |
| x0_lambdas | `scalar_lr`（基准 0.5） | (0.96, 0.95) | 0 | 1e-10 | ❌ |
| smear_params（smear_gate + smear_lambda + backout_lambda） | `0.2`（硬编码） | (0.8, 0.95) | 0 | 1e-10 | ❌ |

> ⚠️ **表里的 LR 是函数签名默认值，不是训练脚本默认值**：`scripts/base_train.py` 的 CLI 默认是 `--unembedding-lr 0.008`、`--embedding-lr 0.3`（签名的 2 倍），预训练**永远**传 CLI 值。按签名默认推实际 LR 会差一倍。所有 AdamW 组的 `eps=1e-10`（远小于常用的 1e-8），对复现很关键。

宽度缩放（μP 风格）**只施加在前三组**（lm_head / embedding / value_embeds），三个标量组用的是绝对值：

```
dmodel_lr_scale = (n_embd / 768) ** -0.5
```

> **不要把两个缩放搞混**（详见 §5.3）：
>
> | 缩放 | 施加位置 | 影响哪些组 |
> |------|---------|-----------|
> | `dmodel_lr_scale = (n_embd/768)**-0.5` | `GPT.setup_optimizer` 内部 | 只有 lm_head / embedding / value_embeds |
> | `batch_lr_scale = (B/B_ref)**0.5` | `base_train.py` 传入 LR 参数之前 | 全部组（因为它改的是 `unembedding_lr`/`embedding_lr`/`scalar_lr`/`matrix_lr` 四个入参） |
>
> 所以上表最后一列的 ❌ 只表示**不做宽度缩放**；`resid_lambdas` / `x0_lambdas` **仍然**会随 batch size 缩放（`scalar_lr` 被乘过 `batch_lr_scale`），而 `smear_params` 连 batch 缩放都不受影响（硬编码 0.2）。
>
> **另一处常见误读**：`scalar_lr` 默认 **0.5**，所以 `resid_lambdas` 的实际 LR 是 **0.005**，比 `x0_lambdas`（0.5）小两个数量级——这是刻意的：resid 缩放参数很敏感，x0 回混需要更快学。

Muon 组：按 `p.shape` 分组（`sorted({p.shape for p in matrix_params})`），同 shape 的矩阵 stack 起来一起算。超参：`lr=matrix_lr`、`momentum=0.95`（**只是初始值**，base_train 每步用调度器覆盖，见 §5.5）、`ns_steps=5`、`beta2=0.9`、`weight_decay` 由调度器每步给。

最后把每组的 `lr` 快照进 `group["initial_lr"]`——**调度器只改 `group["lr"]`，始终以 `initial_lr * multiplier` 计算**，避免累积漂移。

### 2.3 Muon 内核（`nanochat/optim.py#muon_step_fused`）

一个 `@torch.compile(dynamic=False, fullgraph=True)` 图里做**七件事**（旧文档只说四步，已过时）：

1. **Nesterov 动量**
   ```
   momentum_buffer.lerp_(grads, 1 - momentum)
   g = grads.lerp_(momentum_buffer, momentum)
   ```

2. **转 bf16 加速**（仅当 `COMPUTE_DTYPE == bfloat16`）：fp16 在这里不稳定（指数范围不够），fp32 则跳过转换。

3. **MuonEq 行均衡**：把每行缩放到平均行范数，改善进入正交化时矩阵的谱条件数。
   ```
   target   = ||X||_F(dim=最后两维) / sqrt(rows)
   row_norm = ||X||(dim=-1)
   X *= target / row_norm
   ```
   论文：`https://arxiv.org/abs/2603.28254`。

4. **Polar Express 正交化**（`nanochat/optim.py#polar_express_coeffs`）：先把 X 除以自身 Frobenius 范数（乘 1.01 留裕度），然后跑 `ns_steps=5` 次五阶迭代。**高/宽矩阵用两套公式**（`g.size(-2) > g.size(-1)` 走 `A = XᵀX`，否则走 `A = XXᵀ`），避免转置开销。输出类似 `US'Vᵀ`，`S'` 的对角元大致落在 (0.5, 1.5)，源码注释说明这不影响效果。论文：`https://arxiv.org/pdf/2505.16932`。

5. **Muon+ 范数重整**：把 Frobenius 范数拉回 `sqrt(min(m,n))`（精确半正交矩阵的范数），补偿 polar 迭代未完全收敛的误差。论文：`https://arxiv.org/abs/2602.21545`。

6. **NorMuon variance reduction**（factored 二阶动量，做 per-neuron 自适应 LR）：正交化后的各神经元尺度不均匀，用二阶动量归一化。
   ```
   red_dim = -1 if shape[-2] >= shape[-1] else -2          # 沿较长边 reduce
   second_momentum_buffer.lerp_(v_mean, 1 - beta2)
   step_size   = rsqrt(second_momentum_buffer)
   final_scale = step_size * (v_norm / v_norm_new)
   g *= final_scale
   ```
   对应的状态张量形状是 `(chunk, rows, 1)` 或 `(chunk, 1, cols)`——**factored**，所以显存远小于完整二阶矩。论文：`https://arxiv.org/pdf/2510.05491`。

7. **Cautious 权重衰减 + 更新**：只在「更新方向与参数同号」的位置施加 weight decay。
   ```
   mask = (g * stacked_params) >= 0
   stacked_params.sub_(lr * g + lr * wd * stacked_params * mask)
   ```

> Muon **不能**用于 embedding / lm_head / 标量参数（模块 docstring 明确警告）。参数分组的正确性由 `setup_optimizer` 的 assert 守。

### 2.4 AdamW 内核（`nanochat/optim.py#adamw_step_fused`）

`weight_decay → momentum_update → bias_correction → param_update` 融合进一个编译图：

```
p32.mul_(1 - lr*wd)                     # 解耦 weight decay，先施加
exp_avg32.lerp_(grad32, 1 - beta1)
exp_avg_sq32.lerp_(grad32.square(), 1 - beta2)
bias1 = 1 - beta1**step;  bias2 = 1 - beta2**step
denom = (exp_avg_sq32 / bias2).sqrt() + eps
p32.add_(exp_avg32 / denom, alpha = -(lr / bias1))
copy back → p, exp_avg, exp_avg_sq
```

两个关键设计：

- **显式 fp32 计算再写回**：因为 `wte` / `value_embeds` 存的是 bf16，而 bf16 下 `1 - beta2` 这类标量算术会丢掉几乎全部精度；MPS 还会在混合 dtype 上直接报错。cast 由 `torch.compile` 融合掉。
- **0-D CPU 张量传超参**：`self._adamw_lr_t` 等一批 CPU 标量张量每步 `fill_`，传进内核。如果直接传 Python float，超参每变一次就会触发一次重新编译。

### 2.5 分布式：ZeRO-2 三阶段（`nanochat/optim.py#MuonAdamW.step`）

`step()` 里先判定 `dist.is_available() and dist.is_initialized()`，否则 `rank=0, world_size=1`，所有通信路径自然退化成原地整参更新。三个 Phase（docstring 有完整说明）：

```
Phase 1 (_reduce_*):       启动所有 async reduce，不等待
Phase 2 (_compute_*):      逐 group 等 reduce → 算更新 → 立即启动 async gather
                           （早启动的 gather 与后面 group 的 compute 重叠）
Phase 3 (_finish_gathers): 等 gather → 把结果写回原始参数张量
```

**AdamW 通信**（`_reduce_adamw` / `_compute_adamw`）：

| 参数规模 | 通信 | 状态 |
|---------|------|------|
| `numel < 1024` | `all_reduce(AVG)` 梯度 | 状态**复制**在每 rank（但这些参数很小：标量、bias） |
| 大参数 | `reduce_scatter_tensor(AVG)` 梯度 → 各 rank 只得 `1/N` | `exp_avg`/`exp_avg_sq` **分片**，每 rank 只存自己那片 |
| 大参数（回写） | `all_gather_into_tensor` | 把分片拼回完整参数 |

大参数分片要求 `param.shape[0] % world_size == 0`，不满足会 assert 失败。

**Muon 通信**（`_reduce_muon` / `_compute_muon`）：

```
把一个 Muon 组里 K 个同 shape 参数 stack 成 (K, *shape)
chunk_size      = ceil(K / N)
padded          = chunk_size * N
stacked_grads   = 零填充到 (padded, *shape)     # K 不整除时 pad
reduce_scatter  → 各 rank 拿到自己那 chunk
只在自己 chunk 上算 Muon（momentum_buffer / second_momentum_buffer 也是分片的）
all_gather      → 拼回 (padded, *shape)
写回时只取前 K 个（torch._foreach_copy_ + unbind(0)）
```

**LR 的矩阵形状缩放**：Muon 组每步实际用的 LR 是

```
lr * max(1.0, shape[-2] / shape[-1]) ** 0.5
```

也就是对「高瘦」矩阵按长宽比开方放大 LR（源码在 `_compute_muon` 里对 `_muon_lr_t` 做的 `fill_`）。

**buffer 复用**：Muon 的 `stacked_grads` 在 reduce_scatter 之后被复用为 all_gather 的**输出**缓冲（`stacked_params = info["stacked_grads"]`），省下一份 `(padded, *shape)` 的显存。

> 这就是「不依赖 PyTorch DDP 的自实现分布式训练」。好处是没有 DDP 的 bucket/overlap 黑盒，通信完全可控；代价是梯度同步发生在 `optimizer.step()` 里而不是 backward 期间，所以 backward 结束前各 rank 的梯度是不一致的（对 checkpoint/调试有影响）。

## 3. 精度 / dtype 管理

### 3.1 `COMPUTE_DTYPE` 解析（`nanochat/common.py#_detect_compute_dtype`）

优先级：

```
NANOCHAT_DTYPE 环境变量（bfloat16|float16|float32）  >  CUDA SM>=80 用 bf16  >  否则 fp32
```

`COMPUTE_DTYPE_REASON` 记录判定原因，训练启动时打印；`_DTYPE_MAP` 负责字符串映射。

### 3.2 混合精度实现

- **不用 autocast**。自定义 `Linear.forward` 把权重 cast 到输入 dtype（`nanochat/gpt.py#Linear`）。
- master 权重保持 **fp32**（优化器精度）；embedding 与 value_embeds 直接以 `COMPUTE_DTYPE` 存（省显存）。
- rotary cos/sin 也 cast 到 `COMPUTE_DTYPE`，并在 forward 里 `assert self.cos.dtype == COMPUTE_DTYPE` 守住。
- forward 里还 assert 了 `T <= self.cos.size(1)`（超出预算的 rotary 长度会明确报错，而不是静默出错）和 `idx.device == self.cos.device`。

### 3.3 fp16 与 GradScaler

- fp16 训练自动启用 `torch.amp.GradScaler`（`scripts/base_train.py:GradScaler`）；bf16 与 fp32 不需要（bf16 指数范围与 fp32 相同）。
- 分布式下各 rank 独立可能遇到 inf/nan，用 `all_reduce(found_inf, MAX)` 让所有 rank 一致跳步——否则一半 rank 跳步、一半不跳会造成参数分叉（`scripts/base_train.py:single training step`）。
- fp16 下 embedding 必须保持 fp32（GradScaler 无法 unscale fp16 梯度）。
- **RL 暂不支持 fp16**（`README.md#Precision / dtype`），SFT 支持。

### 3.4 FP8（`scripts/base_train.py:FP8 training initialization`）

- `--fp8` 把满足条件的 `Linear` 转 `Float8Linear`，**必须在 `torch.compile` 之前**（编译后再换层等于白换）。
- 过滤条件（`fp8_module_filter`）：in/out features 都被 16 整除（FP8 硬件要求）、最小边 ≥128。启动时会打印 `converted X/Y linear layers, skipped Z (too small)`。
- 非 CUDA 上传 `--fp8` 只打印警告并忽略。
- `--fp8-recipe` **实际上只有 `tensorwise` 能跑**（默认值）：`nanochat/fp8.py#Float8LinearConfig.from_recipe_name` 对任何非 `tensorwise` 的取值直接抛 `ValueError`（"Rowwise/axiswise recipes require the full torchao library"）。
  > ⚠️ **这是一个坑**：`scripts/base_train.py` 的 argparse 把 `rowwise` 列进了 `choices`，所以 `--fp8-recipe rowwise` 能通过**参数校验**，然后在初始化 FP8 时**崩溃**。要用 rowwise 得换回完整 torchao（源码里留了一行注释掉的 `from torchao.float8 import ...`）。
- 评估（val bpb / CORE / 采样）统一包在 `disable_fp8` 里换回 BF16，保证指标可比；`disable_fp8` 的实现是把 `Float8Linear` 模块整体替换回 `nn.Linear` 再恢复（因为 `CastConfig` 是 frozen dataclass，不能原地改字段）。
- 无 fp8 硬件可省略，bf16 精度更高。
- **数值机制**（`nanochat/fp8.py#_to_fp8` / `_Float8Matmul`）：前向的 input/weight 用 **e4m3**（3 位尾数、动态范围小但精度高），梯度用 **e5m2**（2 位尾数、动态范围大以容纳梯度尖峰）；前向 matmul 走 `use_fast_accum=True`（FP8 累加更快），反向走 `False`（梯度累加要精确）。`_Float8Matmul` 是自定义 autograd Function，反向路径就在这里。torch.compile 把它当作 opaque node 处理——这是选 torchao 轻量子类实现而非完整 torchao 的一个取舍点。

## 4. 分布式（DDP）

### 4.1 启动与初始化（`nanochat/common.py#compute_init`）

- `torchrun --nproc_per_node=N` 注入 `RANK/LOCAL_RANK/WORLD_SIZE`（`is_ddp_requested` 检测）。
- `compute_init` 做的事：
  - 每进程绑定 `cuda:local_rank`；
  - `dist.init_process_group(backend="nccl", device_id=device)`；
  - 设 `torch.set_float32_matmul_precision("high")`（tf32）；
  - `torch.manual_seed(42)`（多数代码用显式 rng；全局 seed 主要影响模型权重初始化）；
  - `dist.barrier()` 收尾，保证所有 rank 初始化完成后再继续。
- `scripts/base_train.py` 顶部还设了 `PYTORCH_ALLOC_CONF=expandable_segments:True`——影响显存碎片行为，长训练（checkpoint 频繁存取、fp8 换层）下减少 OOM。
- **必须设 `OMP_NUM_THREADS=1`**（`AGENTS.md`、`runs/speedrun.sh` 开头），否则每个 rank 会开满线程导致严重争抢。

### 4.2 单机回退

省略 `torchrun` 时 `is_ddp_requested()` 为 False，`compute_init` 不建进程组，于是：

- 训练脚本用梯度累积补齐 batch（`scripts/base_train.py:Training loop` 前的 grad_accum 计算）；
- `MuonAdamW.step()` 走 `world_size=1` 分支，无任何通信；
- 结果与分布式**基本一致**（同样的 total_batch_size、同样的调度），差异只来自数据划分与浮点归约顺序。

### 4.3 多 rank 协作约定

- `print0`/`log0` 只在 rank 0 输出/落盘；
- checkpoint 模型只 rank 0 存，优化器分片每 rank 各存各的（`nanochat/checkpoint_manager.py#save_checkpoint`）；
- 评估指标用 `all_reduce` 汇总（`nanochat/core_eval.py#evaluate_task`、`nanochat/loss_eval.py#evaluate_bpb`）；
- SFT 的 `last_step` 用 `all_reduce(MAX)` 跨 rank 同步避免挂死；
- CORE / CORE 类评估**所有 rank 都参与**（数据按 rank 分派），采样只在 master 上做；
- 分布式时 RL 的 reward 均值用 `all_reduce(AVG)` 汇总（`scripts/chat_rl.py`）。
- **梯度同步时机**：发生在 `optimizer.step()` 内部（reduce_scatter/all_reduce），backward 期间各 rank 的 `.grad` 是不一致的——调试梯度时要注意这一点。

## 5. 超参推导与调度

### 5.0 模型形状推导（`scripts/base_train.py#build_model_meta`）

「单一旋钮 `--depth`」到模型形状的换算就发生在这里：

```
model_dim = ceil(depth * aspect_ratio / head_dim) * head_dim   # 向上取整到 head_dim 的倍数
num_heads = model_dim // head_dim
n_kv_head = num_heads                                            # 默认无 GQA
```

- `--aspect-ratio` 默认 **64**（宽深比），`--head-dim` 默认 **128**。`ceil` 保证 `model_dim` 是 `head_dim` 的整数倍，`num_heads` 直接整除得出。
- 这也是「奇数 depth 不推荐」的原因之一：换算出的宽度/head 组合不容易整齐。
- 例：`depth=24` → `24*64/128 = 12` → `model_dim = 1536`，`num_heads = 12`。

### 5.1 训练 token 数（`scripts/base_train.py#get_scaling_params`）

- `get_scaling_params(m) = transformer_matrices + lm_head`——经验上这组参数给出最干净的 scaling law（源码注释指向 `dev/LOG.md`）。
- `target_tokens = target_param_data_ratio * num_scaling_params`，默认 ratio 12（Chinchilla 是 20；speedrun 用 8 故意略欠训以压时间）。
- `num_iterations` 优先级（`scripts/base_train.py` 中 `num_iterations` 的三分支）：

  ```
  --num-iterations >  --target-flops >  --target-param-data-ratio
  ```

  三者至少一个 > 0，否则 `assert` 失败。`--target-flops` 分支用 `round(target_flops / (num_flops_per_token * total_batch_size))`。

- 最后会打印 `Tokens : Scaling params ratio`——**这是校验 scaling law 是否生效的最直接指标**（默认配置下应接近 12）。

### 5.2 batch size

参考 Power Lines 论文 `B_opt ∝ D^0.383`（`https://arxiv.org/abs/2505.13738`）：

```
D_REF = ratio * get_scaling_params(build_model_meta(12))   # d12 是调参基准
B_REF = 2**19 = 524288                                     # d12 最优 batch（实测）
total_batch_size = 2 ** round(log2(B_REF * (target_tokens/D_REF) ** 0.383))
```

- 可以用 `--total-batch-size` 直接覆盖（此时跳过上述推导）。
- 取整到最近的 2 的幂是效率考虑。
- 直觉：D 从 d12 翻到 d24 时，B 只涨 `2^0.383 ≈ 1.3x`。

### 5.3 LR 与 weight decay 缩放

```
batch_ratio   = total_batch_size / B_REF
batch_lr_scale = batch_ratio ** 0.5                 # η ∝ √(B/B_ref)
```

- AdamW 的 `√` 缩放是标准做法；**Muon 也照用同一套**——源码注释明确承认这是未被仔细研究的假设（「hoping it ~works for Muon too」）。
- `batch_lr_scale` 在 `setup_optimizer` 调用时乘进**四个入参**：

  ```
  setup_optimizer(unembedding_lr = args.unembedding_lr * batch_lr_scale,
                  embedding_lr   = args.embedding_lr   * batch_lr_scale,
                  scalar_lr      = args.scalar_lr      * batch_lr_scale,   # 注意：见下
                  matrix_lr      = args.matrix_lr      * batch_lr_scale)
  ```

  > ⚠️ **`scalar_lr` 传进去了，但标量组实际上不受影响**：`setup_optimizer` 内部把 `resid_params` 的 LR 写成 `scalar_lr * 0.01`、`x0_params` 写成 `scalar_lr`，这两组**确实**继承了缩放；但 `smear_params` 用的是硬编码 `0.2`，`value_embeds` 是 `embedding_lr * dmodel_lr_scale * 0.5`。所以「乘进各组 LR」这个说法不准确——**准确说法是「乘进四个 LR 入参，再由 `setup_optimizer` 决定各组怎么用」**。

weight decay 采用 T_epoch 框架（`https://arxiv.org/abs/2405.13698`），核心是 `T_epoch = B/(η·λ·D)` 保持常数。因为 `η ∝ √(B/B_ref)`，可推出：

```
weight_decay_scaled = weight_decay * sqrt(total_batch_size / B_REF) * (D_REF / target_tokens)
```

### 5.4 学习率调度（`scripts/base_train.py#get_lr_multiplier`）

线性 warmup → constant → 线性 warmdown：

```
it < warmup_steps:                     (it + 1) / warmup_steps
it <= num_iterations - warmdown_iters: 1.0
else:                                  progress * 1.0 + (1 - progress) * final_lr_frac
```

默认 `--warmup-steps=40`、`--warmdown-ratio=0.65`、`--final-lr-frac=0.05`。每步对所有 group 执行 `group["lr"] = group["initial_lr"] * lrm`。

### 5.5 Muon 专属调度

- **momentum**（`scripts/base_train.py#get_muon_momentum`）：前 400 步从 0.85 线性升到 0.97，之后恒定 0.97；warmdown 期间从 0.97 线性降到 0.90。
- **weight_decay**（`scripts/base_train.py#get_weight_decay`）：`weight_decay_scaled * 0.5 * (1 + cos(π·it/num_iterations))`，cosine 衰减到 0。
- 两者都只写进 `kind == 'muon'` 的 group。

### 5.6 SFT 的调度差异

SFT 用 `progress`（0→1）而非绝对步数，因为数据驱动停止、`num_iterations` 不一定已知（`scripts/chat_sft.py#get_lr_multiplier`）：

- `--warmup-ratio` 默认 0、`--warmdown-ratio` 0.5、`--final-lr-frac` 0.0（降到 0）；
- `progress = max(progress, approx_progress)`，保证单调不回退；
- `--init-lr-frac` 默认 **0.8**（SFT 起始 LR 是 base 的 80%）：在 `setup_optimizer` 之后对每组乘 `args.init_lr_frac`，**并把结果写回 `initial_lr`**（否则后续调度会按 base LR 算）；
- momentum 前 300 步 0.85→0.95（`scripts/chat_sft.py#get_muon_momentum`，用 `min(it/300, 1)` 线性插值）；
- SFT 的 `weight_decay` 恒为 0（预训练末尾已 cosine 衰减到 0）。

## 6. 训练循环机制（`scripts/base_train.py:Training loop`）

这是「训练到底怎么跑」的完整拆解。

### 6.1 循环骨架

```python
while True:
    last_step = (step == num_iterations)      # 多跑 1 次以在末尾 eval/save
    # 周期性：val bpb / CORE / 采样 / 存 checkpoint
    if last_step: break
    # 单步：
    for micro_step in range(grad_accum_steps):
        loss = model(x, y)
        train_loss = loss.detach()
        loss = loss / grad_accum_steps        # 因为 .backward() 是梯度累加，这里先归一化
        (scaler.scale(loss) if fp16 else loss).backward()
        x, y, dataloader_state_dict = next(train_loader)   # 关键：预取下一批
    # 设调度 → optimizer.step() → zero_grad
    # fp16 时顺序是（见 §3.3 的 found_inf 同步）：
    #   scaler.unscale_(optimizer) → all_reduce(found_inf, MAX)
    #   → scaler.step(optimizer) → scaler.update()
    #   即 unscale 在调度设定之后、step 之前
```

两个容易忽略的点：

1. **`num_iterations + 1` 次循环**：`last_step` 那一轮不训练，只做 eval/save，所以最后一次的指标对应「训完」状态。
2. **预取**：`next(train_loader)` 放在 backward **之后**，此时 GPU 正在算反向，CPU 侧同时完成打包与 HtoD，把数据准备完全藏在计算后面。训练循环只需要一次 `next()` 初始化。

### 6.2 梯度累积与 batch 尺寸

```
tokens_per_fwdbwd      = device_batch_size * max_seq_len        # 单 rank 单次 fwd/bwd
world_tokens_per_fwdbwd = tokens_per_fwdbwd * ddp_world_size     # 全 rank
assert total_batch_size % world_tokens_per_fwdbwd == 0
grad_accum_steps = total_batch_size // world_tokens_per_fwdbwd
```

- `--device-batch-size` 理想值 32（配合 seq 2048 × 8 GPU = 524288 总 batch）。OOM 时按 2 的幂递减（16/8/4/2/1），`grad_accum_steps` 自动补齐。
- `assert` 会明确报出 `total_batch_size must be a multiple of X`，比静默出错好诊断。
- **`loss / grad_accum_steps` 与 `ReduceOp.AVG` 的组合**：micro-step 内是相加（`backward` 累加梯度），跨 rank 时是取平均。所以等价于「所有 micro-batch 的平均梯度」，与单卡大 batch 的语义一致。

### 6.3 每步的四类周期性工作

| 频率开关 | 默认 | 内容 | 注意 |
|---------|------|------|------|
| `--eval-every` | 250 | val bpb | 包 `disable_fp8`；所有 rank 参与；`eval_steps` 按 `--eval-tokens` 折算 |
| `--core-metric-every` | 2000 | CORE 指标 | 用 `orig_model`（未编译），因为输入形状会变；包 `disable_fp8` |
| `--sample-every` | 2000 | 7 个固定 prompt 采样 | **仅 master**；温度 0；用 `orig_model` 避免触发重编译 |
| `--save-every` | -1 | 存 checkpoint | -1 表示只在最后存；条件里 `step > 0` 会跳过 **step 0**，且也会跳过 `resume_from_step` 那一步 |

四个开关都支持 -1/0 关闭。默认配置下 CORE 与采样同频，都是每 2000 步一次。

> **为什么要用 `orig_model`**：`torch.compile(dynamic=False)` 的模型绑定固定输入形状，而 CORE 评估与采样的 batch/seq 形状与训练不同，喂给编译模型会触发重量级重编译。所以脚本保留 `orig_model` 引用，训练用编译版、评估用原始版。

### 6.4 逐 step 计时与 MFU

```
dt            = t1 - t0                                  # 含 fwd + bwd + optimizer.step
tok_per_sec   = total_batch_size / dt
flops_per_sec = num_flops_per_token * total_batch_size / dt
mfu           = 100 * flops_per_sec / (gpu_peak_flops * ddp_world_size)
if step > 10: total_training_time += dt                   # 只统计第 10 步之后
```

- `num_flops_per_token` 来自 `GPT.estimate_flops()`（**前向+反向 = 6 × 参与 matmul 的参数（即所有 `Linear` 权重）+ attention**）。
- **step 0~10（共 11 步）不计入 `total_training_time`**，因为前几步包含 `torch.compile` 首次编译与 cudnn autotune，不代表稳态（源码注释写「after the first 10 steps」，条件是 `step > 10`，严格说是「第 11 步起才计」）。
- ETA 用「第 10 步之后的平均步时」外推（`steps_done = step - 10`）。
- CPU/MPS 上 `gpu_peak_flops = inf`，MFU 无意义（打印为 0）。

### 6.5 显存与 GC 管理

- **meta device 建模型**：`build_model_meta` 在 `torch.device("meta")` 下建模型（只有形状/dtype），再 `to_empty(device=...)` 一次性分配，避免「先在 CPU 建再搬 GPU」造成的峰值翻倍。
- **GC 冻结**：第一步之后 `gc.collect()` → `gc.freeze()` → `gc.disable()`，此后每 5000 步手动 `gc.collect()`。源码注释解释了原因：GC 会周期性花约 500ms 扫描循环引用却只清掉极少量对象，属于纯浪费。
- 结尾打印 `torch.cuda.max_memory_allocated()`（仅 CUDA）。

### 6.6 日志

每步 `print0` 一行（loss EMA、lrm、dt、tok/sec、mfu、epoch、总时间、ETA），每 100 步 `wandb_run.log`（`base_train`）/ 每 10 步（`chat_sft`）。

- loss EMA：`smooth = 0.9*smooth + 0.1*loss`，并用 `1 - 0.9**(step+1)` 做**去偏**，所以第一步打印的值就是真实 loss 而不是 0.1 倍。
- epoch 列同时显示 `pq_idx` / `rg_idx`，方便确认数据加载位置与 resume 正确性。

## 7. 数据加载机制（`nanochat/dataloader.py`）

### 7.1 为什么需要 BOS-aligned best-fit

朴素做法是把所有文档 token 首尾相接再切成固定长度窗口。问题：一个窗口里的大多数 token 看不到自己文档的开头（BOS），上下文是「困惑」的。

nanochat 的做法（`nanochat/dataloader.py` 模块 docstring）：

- **每行都以 BOS 开头**，因此每个 token 都能回看到 BOS、看到完整文档上下文；
- **best-fit**：从缓冲区里挑能整段塞下的最长文档，重复直到没有文档能塞下；
- **最后裁剪**一份最短的文档填满剩余空间（保证 100% 利用率、无 padding）。

代价：**约 35% 的 token 因裁剪被丢弃**（T=2048 时实测）。docstring 也给了回退方案链接（极度缺数据且文档很长时用旧的 packing 方式）。

### 7.2 best-fit 算法（`nanochat/dataloader.py#tokenizing_distributed_data_loader_with_state_bos_bestfit`）

```
对每一行:
  pos = 0
  while pos < row_capacity(T+1):
      确保 doc_buffer 至少有 buffer_size(=1000) 份文档
      remaining = row_capacity - pos
      在 buffer 里找「长度 ≤ remaining 且最长」的文档
      若找到: 整段放入, pos += doc_len, 从 buffer pop
      否则:   取 buffer 里最短的文档, 截断填满 remaining, pos = row_capacity
```

- 选择「最短的」来裁剪是刻意的：**最小化被丢弃的 token 数**。
- `doc_buffer` 是先入先出的池子，`refill_buffer` 批量编码（`num_threads=4`，每批 128 份文档）。

### 7.3 零拷贝传输

```
row_buffer  = torch.empty((B, T+1))                    # 建行的工作区
cpu_buffer  = torch.empty(2*B*T, pin_memory=use_cuda)  # 布局 [inputs | targets]
gpu_buffer  = torch.empty(2*B*T, device=device)
cpu_inputs  = cpu_buffer[:B*T].view(B, T)
cpu_targets = cpu_buffer[B*T:].view(B, T)              # inputs/targets 只差一个偏移
...
gpu_buffer.copy_(cpu_buffer, non_blocking=use_cuda)    # 单次 HtoD
yield inputs, targets, state_dict
```

**inputs 与 targets 是同一块缓冲的两个错位视图**（`row[:, :-1]` 和 `row[:, 1:]`），所以 labels 天然是 next-token 预测目标，不需要额外分配。

### 7.4 DDP 分片与恢复

- **分片粒度是 parquet row group**：`rg_idx` 从 `ddp_rank` 起，每次 `+= ddp_world_size`。同一时刻各 rank 读不同 row group。
- **恢复**：`resume_rg_idx` 存在 meta json 里；恢复时算 `base_idx = resume_rg_idx // world_size; rg_idx = (base_idx + 1) * world_size + ddp_rank`——**+1 是为了不重复已经训过的数据**，代价是丢掉不到一个「世界大小」的 row group。
- 无限 epoch 迭代：`pq_idx` 走完所有分片后 `epoch += 1` 从头再来，`epoch` 也存进 state_dict。

## 8. SFT 的数据打包差异（`scripts/chat_sft.py#sft_data_generator_bos_bestfit`）

与预训练同为 best-fit，但**塞不下时用 BOS pad 而不是裁剪**：

```
若找到能整段塞下的对话: 整段放入
否则:                  row.extend([bos_token] * remaining)   # pad
                       mask_row.extend([0] * remaining)
                       content_len = 当前长度; break
```

原因是对话**不能裁断**（裁一半的对话会教出错误的格式）。

- **两级 mask**：`render_conversation` 给出的 mask（user/special/tool-output 为 0）→ 先按 mask 把 target 置 -1；再单独把 padding 位置置 -1。
- `row_lengths` 记录每行的真实内容长度（不含 padding），用于第二级 mask。
- 打包时 `consumed += ddp_world_size`（**消费计数**）与 `cursor += ddp_world_size`（**预取指针**）分开跟踪——预取会超前，用 cursor 判断「训完一个 epoch」会早停。
- 停止条件：`consumed >= dataset_size` 或 `it >= num_iterations`。
- 张量构造：`inputs` 是 `int32`、`targets` 是 `int64`（配合 `cross_entropy` 的 dtype 要求），`pin_memory` 后 `non_blocking` 拷贝。
- `progress = max(progress, approx_progress)` 保证 LR 调度单调。

## 9. 指标口径速查

| 指标 | 公式 | 参数 |
|------|------|------|
| MFU（训练） | `100 * (num_flops_per_token * total_batch_size / dt) / (gpu_peak_flops * ddp_world_size)` | `scripts/base_train.py:Training loop` |
| 训练 FLOPs/token | 源码：`6 * num_matmul_params() + attn_flops`，其中 `attn_flops = Σ_layers 12·h·q·min(seq, window)` | `nanochat/gpt.py#GPT.estimate_flops` |
| decode FLOPs/token | `2 * num_matmul_params() + Σ_layers 4·h·q·min(ctx, window)` | `#GPT.estimate_decode_flops` |
| prefill FLOPs | `2 * num_matmul_params() * T + Σ_layers 4·h·q·attended`，其中 `attended = w·(w+1)/2 + (T-w)·w`、`w = min(window, T)`（先线性 ramp 到窗口，再走平台） | `#GPT.estimate_prefill_flops` |
| KV 存储/token | `n_layer * 2 * n_kv_head * head_dim * COMPUTE_DTYPE.itemsize` | `#GPT.kv_bytes_per_token` |
| KV 读取/step | `Σ_layers 2 * n_kv_head * head_dim * itemsize * min(ctx, window)` | `#GPT.kv_read_bytes` |
| MBU（推理） | `100 * ((权重字节 + B * KV读取) / tpot) / peak_bandwidth` | `scripts/infer_bench.py` |

- **MFU 在训练侧**（compute-bound），**MBU 在推理 decode 侧**（bandwidth-bound），两者是不同 roofline 的距离度量。
- 训练 MFU 的 attention 项按每层 window 求和，所以 **`--window-pattern` 会同时影响 MFU 分母口径与推理成本估计**。
