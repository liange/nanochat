# 04 - 模型与训练机制

本章深入 `nanochat/gpt.py` 的模型架构、`nanochat/optim.py` 的混合优化器、精度管理、分布式通信，以及 `scripts/base_train.py` 中由 scaling laws 推导超参的机制。

---

## 1. 模型架构（`nanochat/gpt.py`）

### 1.1 总体特性

GPT 是一个 decoder-only Transformer，注释里列出了关键特性（`gpt.py:1`）：

- **旋转位置编码**（rotary），无单独的可学习位置 embedding；
- **QK norm**（query/key 各做 rms_norm）；
- **token embedding 与 lm_head 权重不共享**（untied）；
- **relu^2 激活**（`F.relu(x).square()`，`gpt.py:137`）；
- embedding 后做一次 norm；
- **rmsnorm 无可学习参数**（`gpt.py:42` 的 `norm`）；
- Linear 层无 bias；
- 支持 **GQA**（`n_kv_head <= n_head`，默认相等即无 GQA）；
- 集成 **Flash Attention 3**。

### 1.2 前向流程（`GPT.forward`，`gpt.py:416`）

```
idx (B,T)
 │
 ├─ 取 rotary cos/sin（推理时按 kv_cache 位置偏移，gpt.py:424）
 ├─ x = wte(idx) → COMPUTE_DTYPE → norm(x)            # gpt.py:428
 ├─ Smear: 把上一 token 的 embedding 混入当前位         # gpt.py:433
 │     gate = smear_lambda * sigmoid(smear_gate(x[:,:24]))
 │     x[1:] += gate * x[:-1]   (训练/prefill)
 │     (decode 单 token时用 kv_cache.prev_embedding)
 ├─ x0 = x  # 保存初始 embedding 给 x0 残差
 ├─ for i, block in transformer.h:                    # gpt.py:456
 │     x = resid_lambdas[i]*x + x0_lambdas[i]*x0      # 残差缩放 + x0 回混
 │     ve = value_embeds[i](idx)  (若有)               # value embedding
 │     x = block(x, ve, cos_sin, window_sizes[i], kv_cache)
 │     if i == n_layer//2: x_backout = x              # 记录中层残差
 ├─ x = x - backout_lambda * x_backout                # 减去中层低级特征
 ├─ x = norm(x)
 ├─ logits = lm_head(x)[:, :vocab_size].float()       # gpt.py:469
 ├─ logits = 15 * tanh(logits/15)                      # logit softcap
 └─ targets 给定 → cross_entropy loss；否则返回 logits
```

几个**非标准结构**值得注意：

1. **Smear**（`gpt.py:182`）：用前一个 token 的 embedding 做廉价 bigram 信息注入，`smear_gate` 只看 embedding 的前 24 维。
2. **resid_lambdas / x0_lambdas**（`gpt.py:180`）：每层可学习的残差缩放与「初始 embedding 回混」系数。初始化分层：浅层 resid 更强、x0 回混更多（`gpt.py:236`）。
3. **Value Embeddings (ResFormer)**（`gpt.py:190`）：交替层有 value embedding，attention 里用 `ve_gate` 控制每 head 把 ve 混进 v（`gpt.py:92`）。`has_ve` 判断奇偶（`gpt.py:53`），最后一层必有。
4. **Backout**（`gpt.py:186`）：在 logit 投影前减去中层残差，去除低级特征。
5. **Logit softcap**（`gpt.py:468`）：`15 * tanh(logits/15)`，平滑限制 logits 范围。

### 1.3 Attention（`CausalSelfAttention`，`gpt.py:65`）

```
q = c_q(x), k = c_k(x), v = c_v(x)        # GQA: n_head 与 n_kv_head 可不同
if ve: v = v + gate*ve  (gate = 3*sigmoid(ve_gate(x[...12])), 0~3)   # value residual
q,k = rotary(q,k); q,k = norm(q),norm(k)  # QK norm
q *= 1.2; k *= 1.2                          # 分裂式 scale，sharper attention
if kv_cache is None:
    y = flash_attn_func(q,k,v, causal=True, window_size=window_size)   # 训练
else:
    y = flash_attn_with_kvcache(q, k_cache, v_cache, k=k, v=v, ...)    # 推理
    if 最后一层: kv_cache.advance(T)
y = c_proj(y.contiguous().view(B,T,-1))
```

- `window_size` 是 `(left, right)` 元组，`(-1, 0)` 表示全上下文，`(N, 0)` 表示滑动窗口。
- 最后一层负责推进 KV cache 位置（`gpt.py:120`）——这是训练/推理一致性的关键约定。

### 1.4 滑动窗口（`_compute_window_sizes`，`gpt.py:285`）

`window_pattern`（默认 `SSSL`）按字符平铺到各层：`S`=短窗口（上下文的 1/4，向上取整到 128 的 FA3 tile），`L`=全上下文。**最后一层固定为 L**（全上下文）。

### 1.5 初始化（`init_weights`，`gpt.py:202`）

- `wte`：normal std=0.8；`lm_head`：normal std=0.001（开始接近随机输出）；
- attn 的 `c_q/c_k/c_v` 用 **Uniform**（避免异常值，`sqrt(3)` 使 std 等价 normal），`c_proj` 零初始化；
- `mlp.c_fc` Uniform（×0.4 缩放），`c_proj` 零初始化；
- `resid_lambdas`：`1.15 - 0.10*i/(n-1)`；`x0_lambdas`：`0.20 - 0.15*i/(n-1)`；
- 各 gate 小正数初始化；
- embedding cast 到 `COMPUTE_DTYPE`（fp16 除外，因 GradScaler 无法 unscale fp16 梯度，`gpt.py:263`）。

### 1.6 朴素生成（`GPT.generate`，`gpt.py:483`）

无 KV cache、逐 token 全量重算的流式生成，主要作**对照基准**（`engine.py` 的 `__main__` 会比对两者一致性，`engine.py:307`）。

## 2. 混合优化器（`nanochat/optim.py`）

### 2.1 设计思想

- **矩阵参数**（attn/mlp 的 2D 权重）用 **Muon**（动量 + 正交化）；
- **其余参数**（embedding、lm_head、各类标量）用 **AdamW**（融合内核）。
- 参数分组在 `GPT.setup_optimizer`（`gpt.py:374`）完成，按 `kind` 字段分派。

### 2.2 参数分组（`gpt.py:374`）

AdamW 组（`gpt.py:393`）：
| 组 | LR | betas | weight_decay |
|----|-----|-------|--------------|
| lm_head | `unembedding_lr` | (0.8,0.96) | 0.01 |
| embedding (wte) | `embedding_lr` | (0.8,0.995) | 0.001 |
| value_embeds | `embedding_lr*0.5` | (0.8,0.995) | 0.01 |
| resid_lambdas | `scalar_lr*0.01` | (0.8,0.95) | 0.05 |
| x0_lambdas | `scalar_lr` | (0.96,0.95) | 0 |
| smear_params | 0.2 | (0.8,0.95) | 0 |

> 所有 AdamW LR 再乘 `dmodel_lr_scale = (model_dim/768)^-0.5`（`gpt.py:389`）—— μP 风格的宽度自适应。

Muon 组（`gpt.py:402`）：按 shape 分组（同 shape 的矩阵 stack 起来一起算），`lr=matrix_lr`，`momentum=0.95`，`ns_steps=5`，`beta2=0.9`，`weight_decay` 由调度器给。

### 2.3 Muon 算法（`muon_step_fused`，`optim.py:91`）

四步融合进一个 `@torch.compile` 图：

1. **Nesterov 动量**：`momentum_buffer.lerp_(grad, 1-momentum)`；`g = grad.lerp_(momentum_buffer, momentum)`。
2. **Polar Express 正交化**（`optim.py:115`）：用 5 次 Newton-Schulz 风格迭代把梯度近似正交化（输出类似 `US'V^T`，S' 在 0.5~1.5 之间，实验证明不影响效果）。bf16 下加速。
3. **Variance reduction（NorMuon，`optim.py:131`）**：factored 二阶动量做 per-neuron 自适应 LR，归一化正交化后不均匀的尺度。
4. **Cautious 更新**（`optim.py:147`）：`mask = (g * param) >= 0`（只更新与梯度同号的权重），`param -= lr*(g + wd*param*mask)`。

> 系数 `polar_express_coeffs`（`optim.py:83`）来自 Polar Express 论文（`optim.py:62` 的引用）。Muon 不应用于 embedding/lm_head/标量参数（`optim.py:169` 警告）。

### 2.4 AdamW 内核（`adamw_step_fused`，`optim.py:21`）

`weight_decay → momentum_update → bias_correction → param_update` 融合。用 0-D CPU 张量传超参，避免值变化触发重编译（`optim.py:16`）。

### 2.5 分布式版 `DistMuonAdamW`（`optim.py:299`）

3 阶段异步通信（`optim.py:311` 的 docstring）：

```
Phase 1: 启动所有 async reduce（reduce_scatter / all_reduce）
Phase 2: 逐 group 等 reduce → 算更新 → 启动 async gather（早的 gather 与晚的 compute 重叠）
Phase 3: 等 gather → 回写
```

- **AdamW 通信**（ZeRO-2 风格）：小参数（<1024 元素）`all_reduce` 后整参更新（状态复制，但很小）；大参数 `reduce_scatter` 梯度，每 rank 只算并存储自己那片（`exp_avg/exp_avg_sq` 分片），再 `all_gather`（`optim.py:371`）。
- **Muon 通信**：同 shape 矩阵 stack 成 `(K, *shape)`，按 chunk 分给各 rank，reduce_scatter → 各 rank 算自己 chunk → all_gather。K 不整除时 zero-pad（`optim.py:389`）。
- **buffer 复用**：Muon 的 `stacked_grads` reduce_scatter 后复用为 all_gather 输出，省显存（`optim.py:497`）。

> 这是「不依赖 PyTorch DDP 的自实现分布式训练」。单机用 `MuonAdamW`，分布式用 `DistMuonAdamW`，工厂在 `gpt.py:410`。

## 3. 精度 / dtype 管理

### 3.1 `COMPUTE_DTYPE` 解析（`common.py:17`）

```
NANOCHAT_DTYPE 环境变量 > CUDA SM>=80 用 bf16 > 否则 fp32
```

### 3.2 混合精度实现

- **不用 autocast**。自定义 `Linear.forward` 把权重 cast 到输入 dtype（`gpt.py:49`）。
- master 权重保持 **fp32**（优化器精度）；embedding 直接以 `COMPUTE_DTYPE` 存（省显存，`gpt.py:263`）。
- rotary cos/sin 也 cast 到 `COMPUTE_DTYPE`（`gpt.py:281`），并在 forward 里 assert 其 dtype（`gpt.py:422`）。

### 3.3 fp16 与 GradScaler

- fp16 训练自动启用 `torch.amp.GradScaler`（`base_train.py:324`），防梯度下溢。
- 分布式下各 rank 独立可能遇到 inf/nan，用 `all_reduce(found_inf, MAX)` 让所有 rank 一致跳步（`base_train.py:533`）。
- fp16 下 embedding 必须是 fp32（GradScaler 无法 unscale fp16 梯度，`gpt.py:263`）。
- **RL 暂不支持 fp16**（`README.md:122`），SFT 支持。

### 3.4 FP8（`base_train.py:168`）

- `--fp8` 在 torch.compile 前把 `Linear` 转 `Float8Linear`（H100+，默认 tensorwise scaling）。
- 评估时用 `disable_fp8` 上下文换回 BF16 保证精度（`base_train.py:195`）。
- 无 fp8 硬件可省略，bf16 精度更高，可适当降低 `--target-param-data-ratio`。

## 4. 分布式（DDP）

### 4.1 启动与初始化

- `torchrun --nproc_per_node=N` 注入 `RANK/LOCAL_RANK/WORLD_SIZE`（`common.py:136`）。
- `compute_init`（`common.py:173`）：
  - 每进程绑定 `cuda:local_rank`；
  - `dist.init_process_group(backend="nccl", device_id=device)`；
  - 设 `torch.set_float32_matmul_precision("high")`（tf32）；
  - `torch.manual_seed(42)`（多数代码用显式 rng，全局 seed 主要影响模型权重初始化，`common.py:182`）。
- 必须设 `OMP_NUM_THREADS=1`（`AGENTS.md`、`runs/speedrun.sh:14`）。

### 4.2 单机回退

省略 `torchrun` 时 `is_ddp_requested()` 为 False，`compute_init` 不建进程组，训练脚本自动用梯度累积补齐 batch（`base_train.py:410`），结果基本一致（`README.md:71`）。

### 4.3 多 rank 协作约定

- `print0`/`log0` 只在 rank 0 输出/落盘；
- checkpoint 模型只 rank 0 存，优化器分片每 rank 各存各的（`checkpoint_manager.py:42`）；
- 评估指标用 `all_reduce` 汇总（`core_eval.py:257`、`loss_eval.py:56`）；
- SFT 的 `last_step` 用 `all_reduce(MAX)` 跨 rank 同步避免挂死（`chat_sft.py:341`）。

## 5. Scaling laws 超参推导（`base_train.py:263`）

这是「单一旋钮 `--depth`」能自动算出所有超参的核心机制。

### 5.1 训练 token 数

- `get_scaling_params(model)`（`base_train.py:263`）= `transformer_matrices + lm_head`（经验上这组参数给出最干净的 scaling law）。
- `target_tokens = target_param_data_ratio * num_scaling_params`（`base_train.py:269`）—— compute-optimal 的 tokens:params 比例（默认 12，speedrun 用 8 故意略欠训以压时间）。
- `num_iterations` 优先级（`base_train.py:340`）：`--num-iterations` > `--target-flops` > `--target-param-data-ratio`。

### 5.2 batch size

参考 Power Lines 论文 `B_opt ∝ D^0.383`（`base_train.py:277`）：

```
D_REF = ratio * d12_scaling_params   # d12 是调参基准
B_REF = 2^19 = 524288                # d12 最优 batch
total_batch_size = B_REF * (target_tokens / D_REF)^0.383  # 再 round 到最近的 2 的幂
```

### 5.3 LR 与 weight decay 缩放

```
batch_ratio = total_batch_size / B_REF
batch_lr_scale = sqrt(batch_ratio)          # AdamW 风格 sqrt scaling（Muon 也照用，假设）
weight_decay_scaled = wd * sqrt(batch_ratio) * (D_REF / target_tokens)  # 保持 T_epoch 恒定
```

T_epoch 框架（`base_train.py:297`）来自论文，核心是 `T_epoch = B/(η·λ·D)` 应保持常数。因为 LR 用了 `η ∝ √(B/B_ref)`，可推出 `λ ∝ √(B/B_ref)·(D_ref/D)`。

### 5.4 学习率调度（`base_train.py:360`）

线性 warmup → constant → 线性 warmdown：

```
warmup (默认 40 步): 线性 0→1
constant: 1.0
warmdown (默认 0.65 * num_iterations): 线性 1→final_lr_frac(0.05)
```

### 5.5 Muon 专属调度

- **momentum**（`base_train.py:372`）：前 400 步 0.85→0.97，之后恒定 0.97，warmdown 期间 0.97→0.90。
- **weight_decay**（`base_train.py:385`）：`wd * 0.5*(1+cos(π·step/num_iterations))`，cosine 衰减到 0。

### 5.6 SFT 的调度差异

SFT 用 `progress`（0→1）而非绝对步数（因数据驱动停止，`num_iterations` 不一定已知）：
- warmup_ratio 默认 0、warmdown_ratio 0.5、final_lr_frac 0.0（降到 0）；
- `init_lr_frac=0.8`：SFT 起始 LR 是 base 的 80%；
- momentum 前 300 步 0.85→0.95（`chat_sft.py:324`）。

## 6. 训练循环关键细节（`base_train.py:416`）

```python
while True:
    last_step = (step == num_iterations)          # 多跑 1 次以在末尾 eval/save
    # 周期性：val bpb / CORE / 采样 / 存 checkpoint
    if last_step: break
    # 单步：grad_accum_steps 次 fwd/bwd → 设调度 → optimizer.step
    for micro_step in range(grad_accum_steps):
        loss = model(x, y) / grad_accum_steps
        (scaler.scale(loss) if fp16 else loss).backward()
        x, y, state = next(train_loader)         # 预取下一批（GPU 忙时）
    optimizer.step(); model.zero_grad(set_to_none=True)
    # 日志：EMA loss、tok/sec、MFU、ETA
```

- 梯度累积步数 `grad_accum_steps = total_batch_size // (device_batch_size * seq_len * world_size)`（`base_train.py:410`）。
- `device-batch-size` OOM 时按 2 的幂递减（32→16→8→4→2→1）。
- MFU = `flops_per_sec / (peak_flops * world_size)`（`base_train.py:554`）。
- GC 优化见 [02-核心流程](02-核心流程.md)。
