## 2. `nanochat/gpt.py` —— GPT 模型

核心 nn.Module，定义模型结构、初始化、前向、优化器构建。详细架构见 [04](04-模型与训练机制.md)，这里列接口。

- `GPTConfig`（`gpt.py:29`）：dataclass，含 `sequence_len`、`vocab_size`、`n_layer`、`n_head`、`n_kv_head`（GQA）、`n_embd`、`window_pattern`。
- `GPT`（`gpt.py:154`）：
  - `__init__` 在 **meta device** 上跑（只建形状），真正初始化在 `init_weights()`（`gpt.py:202`）。
  - `forward(idx, targets, kv_cache, loss_reduction)`（`gpt.py:416`）：训练时 `targets` 给出则返回 cross_entropy loss；推理时给 `kv_cache` 返回 logits。
  - `init_weights()`（`gpt.py:202`）：集中初始化所有参数（embedding normal、attn 用 Uniform、c_proj 零初始化、resid/x0 lambda 分层初始化等）。
  - `setup_optimizer(...)`（`gpt.py:374`）：把参数分成 AdamW 组与 Muon 组，返回 `MuonAdamW` / `DistMuonAdamW`。
  - `estimate_flops()`（`gpt.py:317`）：估算每 token 前向+反向 flops（MFU/tokens-per-sec 用）。
  - `num_scaling_params()`（`gpt.py:345`）：返回各类参数计数（wte/lm_head/transformer_matrices/scalars），供 scaling laws 分析。
  - `generate(tokens, max_tokens, ...)`（`gpt.py:483`）：**朴素的**自回归流式生成（无 KV cache，逐 token 全量重算），主要作对照基准。
- 子模块：`CausalSelfAttention`（`gpt.py:65`，GQA + rotary + QK norm + value residual）、`MLP`（`gpt.py:129`，relu^2）、`Block`（`gpt.py:142`）。
- 自定义 `Linear`（`gpt.py:45`）：前向时把权重 cast 到输入 dtype，替代 autocast。
- `norm(x)`（`gpt.py:42`）：`F.rms_norm`，无可学习参数。
- `apply_rotary_emb(x, cos, sin)`（`gpt.py:57`）：旋转位置编码。

## 3. `nanochat/optim.py` —— Muon + AdamW 混合优化器

| 类 | 位置 | 用途 |
|----|------|------|
| `adamw_step_fused` | `optim.py:21` | `@torch.compile` 的融合 AdamW 内核（0-D CPU 张量传参避免重编译） |
| `muon_step_fused` | `optim.py:91` | 融合 Muon 内核：momentum → Polar Express 正交化 → variance reduction → cautious 更新 |
| `MuonAdamW` | `optim.py:154` | **单机版**，矩阵参数走 Muon、其余走 AdamW |
| `DistMuonAdamW` | `optim.py:299` | **分布式版**，ZeRO-2 风格分片 + 3 阶段异步通信 |

接口遵循 PyTorch `Optimizer`：`param_groups` 中每个 group 带 `kind: 'adamw' | 'muon'` 及各自超参。`step()` 按 kind 分派（`optim.py:286 / :509`）。

- Muon 组要求组内参数形状一致，会 stack 起来一次性算（`optim.py:236`），按 shape 分组由 `GPT.setup_optimizer` 完成（`gpt.py:402`）。
- 分布式通信：reduce_scatter 梯度 → 各 rank 只算自己那份 → all_gather 回写；AdamW 大参数 reduce_scatter、小参数（<1024 元素）all_reduce（`optim.py:371`）。
- 算法原理与 LR 缩放见 [04](04-模型与训练机制.md)。

## 4. `nanochat/dataloader.py` —— 分布式数据加载

核心函数 `tokenizing_distributed_data_loader_with_state_bos_bestfit`（`dataloader.py:74`），特点：

- **BOS-aligned + Best-Fit Cropping**：每行以 BOS 开头，用 best-fit 算法从缓冲区挑能整段塞下的最长文档；塞不下时裁剪最短文档填满剩余空间。100% 利用率（无 padding），约 35% token 因裁剪被丢弃（`dataloader.py:1` 的 docstring）。
- **边 tokenize 边打包**：`refill_buffer` 用 tokenizer 批量编码文档（多线程），避免预 tokenize 占盘。
- **DDP 分片**：按 parquet 的 row_group 隔跨分配（`rg_idx += ddp_world_size`，`dataloader.py:68`）。
- **断点续训**：yield 时附带 `state_dict = {pq_idx, rg_idx, epoch}`（`dataloader.py:157`），训练脚本把它存进 checkpoint。
- **零拷贝传输**：预分配 `[inputs | targets]` 的连续 CPU pinned buffer 与 GPU buffer，单次 HtoD（`dataloader.py:111`）。
- `_document_batches`（`dataloader.py:25`）：无限多 epoch 迭代器，处理 DDP 分片与 resume。
- 简化封装 `tokenizing_distributed_data_loader_bos_bestfit`（`dataloader.py:163`）：yield 时省略 state_dict，供评估用。

> SFT 的打包器在 `scripts/chat_sft.py:187`，用 **best-fit padding**（pad 而非裁剪，pad 位 target=-1），因为对话不能裁断。

## 5. `nanochat/tokenizer.py` —— BPE Tokenizer

两套实现，对外接口一致（`encode`/`decode`/`get_bos_token_id`/`encode_special` 等）：

- `HuggingFaceTokenizer`（`tokenizer.py:39`）：基于 HF `tokenizers`，能训练也能推理，主要用来评估 HuggingFace 模型（`base_eval.py` 的 `--hf-path`）。
- `RustBPETokenizer`（`tokenizer.py:163`）：**默认实现**，rustbpe 训练 + tiktoken 推理。`encode_ordinary_batch` 支持多线程批量编码（`tokenizer.py:240`）。

对话相关核心方法（`RustBPETokenizer`）：
- `render_conversation(conversation, max_tokens)`（`tokenizer.py:266`）：把对话渲染成 `(ids, mask)`，mask=1 表示该位置是 assistant 内容、需训练。处理 user/assistant/python 工具调用/python_output 各种 part 类型（`tokenizer.py:324`）。
- `render_for_completion(conversation)`（`tokenizer.py:367`）：去掉最后一条 assistant 消息、追加 `<|assistant_start|>`，供 RL/生成式评测做补全。
- `visualize_tokenization(ids, mask)`（`tokenizer.py:352`）：调试用，带颜色打印 token 序列。

便捷函数：
- `get_tokenizer()`（`tokenizer.py:390`）：从 `$NANOCHAT_BASE_DIR/tokenizer/` 加载 `RustBPETokenizer`。
- `get_token_bytes(device)`（`tokenizer.py:397`）：加载 bpb 用的 `token_bytes.pt`。

## 6. `nanochat/engine.py` —— 推理引擎与工具调用

详见 [05-推理与评测](05-推理与评测.md)。要点：

- `KVCache`（`engine.py:82`）：为 FA3 `flash_attn_with_kvcache` 设计，张量布局 `(B, T, H, D)`；`prefill()` 支持「batch=1 预填 → 复制成多路」并行采样（`engine.py:123`）。
- `Engine`（`engine.py:169`）：`generate(tokens, num_samples, ...)` 是流式生成器，yield `(token_column, token_masks)`；`generate_batch(...)` 是非流式封装返回最终序列。
- `RowState`（`engine.py:160`）：每条采样序列的状态机，管理 forced_tokens 队列、python 块、完成标志。
- `sample_next_token`（`engine.py:141`）：支持 temperature=0（argmax）/ top-k 采样。
- `use_calculator(expr)`（`engine.py:46`）：计算器工具的安全求值（纯数学表达式 + `.count()` 字符串操作）。

> 引擎**只处理 token id 序列，不碰 tokenization**（`engine.py:9`），tokenization 由调用方负责。这也意味着修改模型前向时必须同步 KV cache 路径。

## 8. `nanochat/core_eval.py` —— CORE 评测

实现 DCLM 论文的 CORE 指标评估。

- 三种任务类型的 prompt 渲染：`render_prompts_mc`（多选，`core_eval.py:17`）、`render_prompts_schema`（schema，`core_eval.py:36`）、`render_prompts_lm`（语言建模，`core_eval.py:56`）。
- `find_common_length`（`core_eval.py:86`）：找多个序列的公共前缀/后缀，定位 continuation 的起止位置。
- `forward_model`（`core_eval.py:144`）：对 `BxT` input 算每位置 loss 与 argmax 预测。
- `evaluate_example`（`core_eval.py:168`）：渲染 prompt → batch → forward → 判分（MC/schema 取最低平均 loss 的选项，LM 看 argmax 是否全对）。
- `evaluate_task`（`core_eval.py:244`）：跨 example 分派到各 rank，all_reduce 汇总正确数。

> CORE 指标的 centered 归一化与汇总在 `scripts/base_eval.py:162`，不在 `core_eval.py` 内。

## 9. `nanochat/loss_eval.py` —— bpb 评估

`evaluate_bpb(model, batches, steps, token_bytes)`（`loss_eval.py:9`）：

- 用 `loss_reduction='none'` 算逐 token loss；
- 按 `token_bytes`（每个 token 的 UTF-8 字节数，特殊 token=0）把 loss 加权，特殊 token 与 mask 位置（target<0）不计入；
- 跨 rank all_reduce 总 nats 与总 bytes，`bpb = total_nats / (ln2 * total_bytes)`（`loss_eval.py:64`）。
- 这使得 bpb **与词表大小无关**，换 tokenizer 后仍可比（前提是数据不变，否则数据变了 bpb 不可比）。

## 10. `nanochat/flash_attention.py` —— 统一注意力接口

导出 `flash_attn` 命名空间（`flash_attention.py:184`），API 与 FA3 完全一致：

- `flash_attn_func(q, k, v, causal, window_size)`（`flash_attention.py:107`）：训练用，`(B,T,H,D)` 布局。
- `flash_attn_with_kvcache(q, k_cache, v_cache, k, v, cache_seqlens, ...)`（`flash_attention.py:131`）：推理用，FA3 原地更新 cache，SDPA 回退手动管理。
- `_resolve_use_fa3()`（`flash_attention.py:48`）：一次性解析是否用 FA3（Hopper + bf16）。
- `_override_impl`（`flash_attention.py:45`）：测试用，强制切 fa3/sdpa。
- SDPA 回退 `_sdpa_attention`（`flash_attention.py:69`）：处理全上下文、单 token、滑动窗口、chunk 推理四种情况。

## 12. `nanochat/execution.py` —— 沙箱化代码执行

为 HumanEval 评测服务（`tasks/humaneval.py` 调用）。

- `execute_code(code, timeout=5.0, maximum_memory_bytes=256MB)`（`execution.py:286`）：在独立子进程执行，返回 `ExecutionResult`。
- 安全措施：`reliability_guard`（`execution.py:134`）禁用 `os.system`/`subprocess.Popen`/`shutil.rmtree` 等危险函数、设内存上限、关闭 stdin；`time_limit` 超时；`capture_io` 捕获 stdout/stderr；`create_tempdir` 临时目录。
- **非真正安全沙箱**：不挡网络、无内核级隔离（`execution.py:13` 警告），仅防意外破坏，不防恶意对抗代码。

## 14. `tasks/` —— 评测/训练任务

- `Task`（`common.py:10`）：基类。属性 `eval_type`（`generative`|`categorical`）；方法 `num_examples()`/`get_example(index)`/`evaluate(problem, completion)`/可选 `reward(...)`。支持切片 `start/stop/step`。
- `TaskMixture`（`common.py:54`）：把多个 Task 的 example 索引确定性 shuffle 后混在一起（`random.Random(42)`），重复传入即过采样。SFT 用。
- `TaskSequence`（`common.py:89`）：顺序拼接多个 Task，用于课程式训练。
- `render_mc`（`common.py:112`）：统一的多选题渲染格式（注意：字母放在选项之后、`=` 与字母间无空格，这是为小模型 token 对齐做的精心设计）。
- 具体任务：`gsm8k.py`（generative，解析 `<<>>` 工具调用，`tasks/gsm8k.py:52`）、`mmlu.py`/`arc.py`（categorical）、`humaneval.py`（generative + 沙箱执行）、`spellingbee.py`/`smoltalk.py`/`customjson.py`。
