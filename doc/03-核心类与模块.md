## 2. `nanochat/gpt.py` —— GPT 模型

核心 nn.Module，定义模型结构、初始化、前向、优化器构建、推理成本建模。

### 2.1 配置与基础件

- `GPTConfig`（`nanochat/gpt.py#GPTConfig`）：dataclass，含 `sequence_len`、`vocab_size`、`n_layer`、`n_head`、`n_kv_head`（GQA）、`n_embd`、`window_pattern`（默认 `SSSL`）。
- `norm(x)`（`nanochat/gpt.py#norm`）：`F.rms_norm`，无可学习参数。
- `Linear`（`nanochat/gpt.py#Linear`）：前向时把权重 cast 到输入 dtype，替代 autocast。
- `apply_rotary_emb(x, cos, sin)`（`nanochat/gpt.py#apply_rotary_emb`）：旋转位置编码，按 -θ 旋转（与教科书转置共轭，功能等价，为 checkpoint 兼容保留）。
- `has_ve(layer_idx, n_layer)`（`nanochat/gpt.py#has_ve`）：判断某层是否有 value embedding；**交替层有，且最后一层必有**（`layer_idx % 2 == (n_layer - 1) % 2`）。
- `CausalSelfAttention`（`nanochat/gpt.py#CausalSelfAttention`）、`MLP`（`#MLP`，relu²）、`Block`（`#Block`）。

### 2.2 `GPT` 的接口

| 方法 | 作用 |
|------|------|
| `GPT.__init__` | 在 **meta device** 上跑（只建形状）；`pad_vocab_size_to=64` 把词表 pad 到倍数以便对齐 |
| `GPT.init_weights` | 集中初始化所有参数 |
| `GPT.forward(idx, targets, kv_cache, loss_reduction)` | 训练时给 `targets` 返回 cross_entropy loss；推理时给 `kv_cache` 返回 logits |
| `GPT.setup_optimizer(...)` | 把参数分成 AdamW 组与 Muon 组，返回 `MuonAdamW` |
| `GPT.generate(tokens, max_tokens, ...)` | **朴素的**自回归流式生成（无 KV cache，逐 token 全量重算），主要作对照基准 |
| `GPT.get_device` | 从 `wte` 权重取设备（引擎用它，避免假定 cuda） |
| `GPT.estimate_flops()` | 估算**训练**每 token 前向+反向 flops（MFU 用） |
| `GPT.num_scaling_params()` | 返回各类参数计数（wte/lm_head/transformer_matrices/scalars），供 scaling laws 分析 |
| `GPT.num_matmul_params()` | 参与 matmul 的参数数（结构化统计：所有 `Linear` 的权重） |
| `GPT.estimate_decode_flops(context_len)` | 推理**单 token decode** 的 flops（每步 2·matmul参数 + 各层 `4·h·q·min(ctx, window)`） |
| `GPT.estimate_prefill_flops(num_tokens)` | 推理 **prefill** 的 flops（因果，token t 只 attend `min(t, window)`，是三角形 ramp + 平台） |
| `GPT.kv_bytes_per_token()` | 每 token 的 KV cache 存储字节数（**乘以层数**，注意是整模型而非单层） |
| `GPT.kv_read_bytes(context_len)` | 给定上下文长度下，decode 一步要读多少 KV 字节（受滑窗封顶） |
| `GPT._compute_window_sizes(config)` | 把 `window_pattern` 平铺成每层的 `(left, right)` 元组 |
| `GPT._precompute_rotary_embeddings(...)` | 预算 rotary cos/sin 并 cast 到 `COMPUTE_DTYPE` |

> **成本建模这一族方法是新增的**，服务于 `scripts/infer_bench.py`：架构选择（GQA、滑窗）对推理成本的影响靠它们量化，所以改动 attention 结构时应同步更新这几个估计函数，否则 MBU/理论上限会失真。

## 3. `nanochat/optim.py` —— MuonAdamW 混合优化器

| 符号 | 作用 |
|------|------|
| `adamw_step_fused` | `@torch.compile(fullgraph=True)` 的融合 AdamW 内核 |
| `muon_step_fused` | 融合 Muon 内核（**7 步**）：momentum → bf16 cast → 行均衡(MuonEq) → Polar Express 正交化 → 范数重整(Muon+) → variance reduction(NorMuon) → cautious 更新 |
| `polar_express_coeffs` | Polar Express 迭代系数（num_iters=5, safety_factor=2e-2, cushion=2） |
| `MuonAdamW` | **唯一的优化器类**，同时覆盖单机与分布式；`step()` 按 `kind` 分派 |
| `MuonAdamW._reduce_adamw` / `._reduce_muon` | Phase 1：启动异步 reduce |
| `MuonAdamW._compute_adamw` / `._compute_muon` | Phase 2：等 reduce、算更新、启动 gather |
| `MuonAdamW._finish_gathers` | Phase 3：等 gather、回写 |
| `MuonAdamW.step` | 三阶段主循环 |

接口遵循 PyTorch `Optimizer`：`param_groups` 中每个 group 带 `kind: 'adamw' | 'muon'` 及各自超参。

- **单机/分布式是同一份代码**：`step()` 里查 `dist.is_available() and dist.is_initialized()`，没有进程组时 `rank=0, world_size=1`，所有通信路径自然退化为「整参原地更新」。旧版本的独立 `DistMuonAdamW` 类**已删除**。
- Muon 组要求组内参数形状一致，会 stack 起来一次性算；按 shape 分组由 `GPT.setup_optimizer` 完成。
- 分布式通信：reduce_scatter（`ReduceOp.AVG`）梯度 → 各 rank 只算自己那份 → all_gather 回写。AdamW 小参数（<1024 元素）走 all_reduce 并复制状态，大参数走 reduce_scatter 分片状态。Muon 按 chunk 分参数，K 不整除时 zero-pad。
- **buffer 复用**：Muon 的 `stacked_grads` reduce_scatter 之后复用为 all_gather 的输出缓冲，省一份显存。
- **0-D CPU 张量传超参**：`_adamw_lr_t` 等一批 `torch.tensor(0.0, device="cpu")`，每步 `fill_` 后传进编译内核，避免超参变化触发 `torch.compile` 重编译。

算法原理与 LR 缩放见 [04](04-模型与训练机制.md) §2。

## 4. `nanochat/dataloader.py` —— 分布式数据加载

核心函数 `tokenizing_distributed_data_loader_with_state_bos_bestfit`（`nanochat/dataloader.py#tokenizing_distributed_data_loader_with_state_bos_bestfit`），特点：

- **BOS-aligned + Best-Fit Cropping**：每行以 BOS 开头；每轮从缓冲区挑**能整段塞下的最长文档**，重复直到没有文档能塞下，最后裁一份最短的填满剩余空间。100% 利用率（无 padding），约 35% token 因裁剪被丢弃（模块 docstring 给了取舍理由：每个 token 都能回看到 BOS、看到完整文档上下文，代价是裁剪率）。
- **边 tokenize 边打包**：内部 `refill_buffer` 用 tokenizer 批量编码文档（多线程 `num_threads=4`，`tokenizer_batch_size=128`）。
- **DDP 分片**：按 parquet 的 row_group 隔跨分配（`rg_idx += ddp_world_size`），所以不同 rank 读到不相交的 row group。
- **断点续训**：yield 时附带 `state_dict = {pq_idx, rg_idx, epoch}`；恢复时从 `resume_rg_idx // ddp_world_size + 1` 处继续（**+1 是为了不重复已训数据**）。
- **零拷贝传输**：预分配 `[inputs | targets]` 的连续 pinned CPU buffer 与 GPU buffer，单次 HtoD（`non_blocking`）。
- `_document_batches`（`nanochat/dataloader.py#_document_batches`）：无限多 epoch 文档批迭代器，处理 DDP 分片与 resume；train 用 `parquet_paths[:-1]`，val 用 `[-1:]`。
- 简化封装 `tokenizing_distributed_data_loader_bos_bestfit`（`#tokenizing_distributed_data_loader_bos_bestfit`）：yield 时省略 state_dict，供评估用。

> SFT 的打包器在 `scripts/chat_sft.py#sft_data_generator_bos_bestfit`，用 **best-fit padding**（pad 而非裁剪，pad 位 target=-1），因为对话不能裁断。

## 6. `nanochat/engine.py` —— 推理引擎与工具调用

详见 [05-推理与评测](05-推理与评测.md)。要点：

- `KVCache`（`nanochat/engine.py#KVCache`）：为 FA3 `flash_attn_with_kvcache` 设计，张量布局 `(n_layers, B, T, H, D)`；`prefill(other)` 支持「batch=1 预填 → 复制成多路」并行采样；`get_layer_cache(layer_idx)` 返回某层视图；`reset()` 清空；`get_pos()` 返回当前位置（滑窗推理正确性依赖它做 RoPE 偏移）；`advance(n)` 把 `cache_seqlens` 加 n；`cache_seqlens` 是 `(B,)` int32 位置计数。
- `sample_next_token`（`#sample_next_token`）：支持 temperature=0（argmax）/ top-k / 全词表三种采样。
- `RowState`（`#RowState`）：每条采样序列的状态机，管理 forced_tokens 队列、python 块、完成标志。
- `Engine`（`#Engine`）：`generate(tokens, num_samples, ...)` 是流式生成器，yield `(token_column, token_masks)`；`generate_batch(...)` 是非流式封装。
- `use_calculator(expr)`（`#use_calculator`）：计算器工具的安全求值（纯数学表达式 + `.count()` 字符串操作，黑名单挡危险模式）。
- `eval_with_timeout` / `timeout`（`#eval_with_timeout`）：用 signal 做 3 秒超时的受限求值。

> 引擎**只处理 token id 序列，不碰 tokenization**（模块 docstring），tokenization 由调用方负责。这也意味着修改模型前向时必须同步 KV cache 路径。
>
> 文件末尾有 `__main__` 内联自测，比对 `model.generate`（朴素）与 `Engine.generate`（KV cache）的输出是否逐 token 一致。**真正的守门测试是 `tests/test_engine.py`。**

## 8. `nanochat/core_eval.py` —— CORE 评测

实现 DCLM 论文的 CORE 指标评估。

- 三种任务类型的 prompt 渲染：`render_prompts_mc`（多选）、`render_prompts_schema`、`render_prompts_lm`（语言建模）。
- batch 组装：`stack_sequences` / `batch_sequences_mc` / `batch_sequences_schema` / `batch_sequences_lm`——渲染后的变长样本按最长 pad（BOS）并记录 continuation 位置，供 `forward_model` 一次算完。
- `find_common_length`：找多个序列的公共前缀/后缀，定位 continuation 的起止位置。
- `forward_model`：对 `BxT` input 算每位置 loss 与 argmax 预测。
- `evaluate_example`：渲染 prompt → batch → forward → 判分（MC/schema 取最低平均 loss 的选项，LM 看 argmax 是否全对）。
- `evaluate_task`：跨 example 分派到各 rank，`all_reduce` 汇总正确数。

> CORE 指标的 centered 归一化与汇总在 `scripts/base_eval.py#evaluate_core`，**不在 `core_eval.py` 内**。

## 9. `nanochat/loss_eval.py` —— bpb 评估

`evaluate_bpb(model, batches, steps, token_bytes)`（`nanochat/loss_eval.py#evaluate_bpb`）：

- 用 `loss_reduction='none'` 算逐 token loss；
- 按 `token_bytes`（每个 token 的 UTF-8 字节数，特殊 token=0）把 loss 加权，特殊 token 与 mask 位置（target<0）不计入；
- 跨 rank `all_reduce` 总 nats 与总 bytes，`bpb = total_nats / (ln2 * total_bytes)`。
- 这使得 bpb **与词表大小无关**，换 tokenizer 后仍可比（前提是数据不变，否则数据变了 bpb 不可比）。

## 10. `nanochat/flash_attention.py` —— 统一注意力接口

导出 `flash_attn` 命名空间，API 与 FA3 完全一致：

- `flash_attn_func(q, k, v, causal, window_size)`：训练用，`(B,T,H,D)` 布局。
- `flash_attn_with_kvcache(q, k_cache, v_cache, k, v, cache_seqlens, ...)`：推理用。**FA3 原地更新 cache；SDPA 回退也手动做同样的原地写入**，保证两条路径语义一致（`nanochat/flash_attention.py#flash_attn_with_kvcache`）。
- `_load_flash_attention_3()`：尝试 import FA3——**只按 major 是否为 9 分支**（`_resolve_use_fa3` 是另一回事）。先 import 也要能过 `torch.cuda.is_available()`；Hopper 用 `varunneal/flash-attention-3`，其他 major 用 `kernels-community/flash-attn3` 并先 `has_kernel()` 探测；异常一律 `return None`。
- `_resolve_use_fa3()`：一次性解析是否用 FA3（可用性 + `_override_impl` + dtype）；结果存 `USE_FA3`。
- `_override_impl`：测试用，强制切 `'fa3'`/`'sdpa'`。
- `_sdpa_attention`（`#_sdpa_attention`）：SDPA 回退，处理**四种情况**——全上下文等长（直接 `is_causal=True`）、单 token 解码（切片取最后 `window+1` 个 key）、滑窗/chunk 推理（显式 bool mask，因为 `is_causal` 在 `Tq != Tk` 时对不齐 cache 位置）。
- GQA 通过 SDPA 的 `enable_gqa` 参数传递，判定条件是 `q.size(1) != k.size(1)`。

## 11. `nanochat/fp8.py` —— FP8 训练

自定义 FP8 实现（比 torchao 精简得多，API 兼容）：
**只实现 tensorwise 一种 recipe**（一个张量一个标量 scale）。

- `Float8LinearConfig.from_recipe_name("tensorwise")`：**只接受这一种取值**；传 `rowwise`/其他会抛 `ValueError`（提示 rowwise 需要完整 torchao）。注意 `scripts/base_train.py` 的 argparse 却允许 `--fp8-recipe rowwise`，所以该组合会通过参数校验后才崩溃。
- `_to_fp8(x, fp8_dtype)`：动态量化，走 `torch._scaled_mm` + cuBLAS 缩放（rowwise 需要 CUTLASS 内核，故未实现）。
- `convert_to_float8_training(module, *, config=None, module_filter_fn=None)`：把符合条件的 `Linear` 转成 `Float8Linear`。
- `Float8Linear`：FP8 线性层，`from_float` 做转换。
- **过滤条件由调用方给**：`scripts/base_train.py` 里的 `fp8_module_filter` 要求 in/out features 被 16 整除、最小边 ≥128（FP8 硬件要求）。
- 训练时启用，评估时用 `disable_fp8` 上下文临时换回 BF16 `nn.Linear` 以保证精度（`scripts/base_train.py#disable_fp8`）。
- 无 fp8 硬件时该模块不被 import（`--fp8` 在非 CUDA 上只打印警告并忽略）。

## 12. `nanochat/execution.py` —— 子进程代码执行

为 HumanEval 评测服务（`tasks/humaneval.py` 调用）。

- `ExecutionResult`（dataclass）：`success` / `stdout` / `stderr` / `error` / `timeout` / `memory_exceeded`。
- `execute_code(code, timeout=5.0, maximum_memory_bytes=256MB)`（`nanochat/execution.py#execute_code`）：在**独立 Python 子进程**中执行代码，返回 `ExecutionResult`。
- 隔离手段是模块级字符串 `GUARD`（`nanochat/execution.py#GUARD`），在子进程里、跑不可信代码之前执行：
  - `resource.setrlimit` 设 `RLIMIT_AS` / `RLIMIT_DATA` / `RLIMIT_STACK`（macOS 上跳过，因为会失败）；
  - 把 `os` 的 `kill`/`system`/`remove`/`rmdir`/`fork`/`chmod`/`chdir` 等一批函数置 `None`，`shutil.rmtree`/`move` 置 `None`，`subprocess.Popen = None`；
  - 清空 `builtins.exit/quit/help`，`faulthandler.disable()`，`sys.modules` 里屏蔽 `ipdb`/`joblib`/`resource`/`psutil`/`tkinter`；
  - 子进程由父进程超时硬杀，stdin 关闭，运行在临时目录里，结束后删除。
- **非真正安全沙箱**（模块 docstring 明确列出未覆盖项）：不挡网络（仍可开 socket）、`ctypes` 等动态特性可绕过、无内核级隔离（无 seccomp/容器）。只防**意外破坏**，不防恶意对抗代码。

> 旧文档提到的 `reliability_guard` / `time_limit` / `capture_io` / `create_tempdir` 这些独立上下文管理器**都不存在**了——现在全部收敛到 `GUARD` 字符串里。

## 13. `tasks/` —— 评测/训练任务

当前只有 6 个文件：`common.py`、`arc.py`、`mmlu.py`、`gsm8k.py`、`humaneval.py`、`smoltalk.py`。

- `Task`（`tasks/common.py#Task`）：基类。属性 `eval_type`（`generative` | `categorical`）；方法 `num_examples()` / `get_example(index)` / `evaluate(problem, completion)` / 可选 `reward(...)`。支持切片 `start/stop/step`。注意：**基类形参名 `problem`/`completion` 与子类实际语义不同**——子类实现传的是对话对象与助手回复文本（如 `tasks/gsm8k.py#GSM8K.evaluate(conversation, assistant_response)`），读子类代码时不要被形参名带偏。
- `TaskMixture`（`tasks/common.py#TaskMixture`）：把多个 Task 的 example 索引确定性 shuffle 后混在一起（固定 seed），重复传入即过采样。SFT 用。
- `TaskSequence`（`tasks/common.py#TaskSequence`）：顺序拼接多个 Task，用于课程式训练。
- `HubDataset`（`tasks/common.py#HubDataset`）：从 HuggingFace Hub 拉数据集的基类（`test_tasks.py` 覆盖）。实际拉数据的入口是 `tasks/common.py#load_hub_dataset`（支持 subset/split 参数），所有 Hub 任务都走它。
- `render_mc`（`tasks/common.py#render_mc`）：统一的多选题渲染格式（注意：字母放在选项之后、`=` 与字母间无空格，这是为小模型 token 对齐做的精心设计）。
- 具体任务：
  - `tasks/gsm8k.py#GSM8K`（generative，解析 `<<>>` 工具调用、抽 `#### 数字` 判分、`reward()` 给 RL 用）；
  - `tasks/mmlu.py#MMLU`、`tasks/arc.py#ARC`（categorical）；
  - `tasks/humaneval.py#HumanEval`（generative + `execution.py` 子进程执行）；
  - `tasks/smoltalk.py#SmolTalk`（HF 通用对话数据）。

> **`SpellingBee` / `SimpleSpelling` / `CustomJSON` 不存在**——旧文档列过这三个，当前仓库里既没有对应文件也没有任何引用。
