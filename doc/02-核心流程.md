# 02 - 核心流程

本章按数据流自上而下走一遍 nanochat 的端到端链路：从原始文本到一个能对话的模型。每个阶段都会指出**输入是什么、输出是什么、由谁负责、关键源码在哪**。

```
┌────────────┐   ┌──────────┐   ┌──────────┐   ┌──────┐   ┌──────┐   ┌──────────┐
│ 1. 数据准备 │──▶│ 2. Token │──▶│ 3. 预训练 │──▶│ 4.SFT│──▶│ 5.RL │──▶│ 6.评估/对话│
│  (parquet) │   │  -izer  │   │  (base)  │   │      │   │      │   │           │
└────────────┘   └──────────┘   └──────────┘   └──────┘   └──────┘   └──────────┘
   dataset.py       tok_train       base_train    chat_sft   chat_rl   base_eval
                     tok_eval                      chat_eval           chat_eval
                                                                  chat_cli / infer_bench
```

## 阶段 1：数据准备

**目的**：把预训练语料以 parquet 分片形式下载到本地。

- 数据集是 **ClimbMix-400B**（HuggingFace `karpathy/climbmix-400b-shuffle`），共 6542 个分片（`nanochat/dataset.py#BASE_URL`、`#MAX_SHARD`）。
- 入口 `python -m nanochat.dataset -n 170`：`-n` 指定下载多少个**训练分片**，最后一个分片固定作为验证集（`nanochat/dataset.py#download_single_file`；`-n` 的解析在文件末尾的 `__main__` 段）。
- 下载支持多进程并发（`multiprocessing.Pool`）、断点续传（跳过已存在文件）、指数退避重试（`nanochat/dataset.py#download_single_file`）。
- 落盘位置：`$NANOCHAT_BASE_DIR/base_data_climbmix/`（`nanochat/dataset.py#DATA_DIR`）。
- 遍历工具 `list_parquet_files` / `parquets_iter_batched`（`nanochat/dataset.py#list_parquet_files`）供 dataloader 和 tokenizer 复用；train/val 划分规则：除最后一个分片外都是 train（`nanochat/dataloader.py#_document_batches` 里的 `parquet_paths[:-1]` / `[-1:]`）。

> 兼容历史：若找不到 ClimbMix 目录，`list_parquet_files` 会回退到旧的 FinewebEdu-100B 并打印升级提示（`warn_on_legacy` 参数）。

## 阶段 2：Tokenizer 训练

**目的**：训练一个 GPT-4 风格的 BPE tokenizer，词表大小默认 32768（2^15）。

- 入口 `scripts/tok_train.py`，默认用前 **2B 字符**训练（`--max-chars` 默认 `2_000_000_000`）。
- 实现是 **rustbpe 训练 + tiktoken 推理** 的组合（`nanochat/tokenizer.py#RustBPETokenizer`）：
  - 训练时 `rustbpe.Tokenizer().train_from_iterator(...)`（`nanochat/tokenizer.py#RustBPETokenizer.train_from_iterator`）；注意训练时词表要减去特殊 token 数（`vocab_size - len(SPECIAL_TOKENS)`）；
  - 训练完构造一个 `tiktoken.Encoding` 供高效推理（同一个 classmethod 内）。
- 分词正则 `SPLIT_PATTERN`（`nanochat/tokenizer.py#SPLIT_PATTERN`）是 GPT-4 风格，但把数字位数从 `\p{N}{1,3}` 改成 `\p{N}{1,2}`，以免在小词表下浪费 token（源码注释说明 2 是 32K 词表的 sweet spot）。
- 特殊 token 在 `SPECIAL_TOKENS`（`nanochat/tokenizer.py#SPECIAL_TOKENS`）定义，用于对话格式与工具调用：
  - `<|bos|>` 文档/序列起始；`<|user_start|>/<|user_end|>`、`<|assistant_start|>/<|assistant_end|>` 包裹对话；
  - `<|python_start|>/<|python_end|>` 触发计算器工具，`<|output_start|>/<|output_end|>` 包裹工具输出。
- **副产物 `token_bytes.pt`**：缓存每个 token id 对应的 UTF-8 字节数（特殊 token 记 0），供 bpb 指标使用（`scripts/tok_train.py` 末尾）。
- 评估 `scripts/tok_eval.py` 报告压缩率（含一段固定文本的逐 token 对照输出）。
- 加载入口 `nanochat/tokenizer.py#get_tokenizer`，默认读 `$NANOCHAT_BASE_DIR/tokenizer/` 下的 `tokenizer.pkl`。

## 阶段 3：预训练（Pretrain）

**目的**：在 ClimbMix 上训练 base 模型，达到 GPT-2 级能力（CORE > 0.256525）。

入口 `scripts/base_train.py`，关键流程：

1. **初始化**（`scripts/base_train.py:Compute init`）：`compute_init` 做 DDP/精度/seed 设置；rank 0 接 wandb，其余用 `DummyWandb`；随后打印 FA3 状态（`USE_FA3`）与 `COMPUTE_DTYPE`。
2. **构建模型（meta device）**（`scripts/base_train.py#build_model_meta`）：先在 meta device 上建模型（只有形状/dtype，无数据），再 `to_empty` 分配显存、`init_weights` 初始化权重（`nanochat/gpt.py#GPT.init_weights`）。这样避免重复分配内存。
3. **断点续训**：`--resume-from-step` 非 -1 时用 `load_checkpoint(..., load_optimizer=True)` 覆盖模型参数并恢复优化器。
4. **可选 FP8**（`scripts/base_train.py:FP8 training initialization`）：把满足条件（in/out features 被 16 整除、最小边 ≥128）的 `nn.Linear` 转成 `Float8Linear`。**必须在 `torch.compile` 之前做**。同时定义 `disable_fp8` 上下文管理器，评估时临时换回 BF16 `nn.Linear` 保证精度（`scripts/base_train.py#disable_fp8`）。
5. **torch.compile**：`dynamic=False`（输入形状固定），同时保留 `orig_model` 用于推理/评估/存盘（因为 compile 后形状会变）。
6. **超参推导**（`scripts/base_train.py:Scaling laws`）：根据 scaling laws 自动算出训练 token 数、batch size、LR 缩放、weight decay（详见 [04-模型与训练机制](04-模型与训练机制.md) §5）。
7. **优化器**（`scripts/base_train.py:Initialize the Optimizer`）：`model.setup_optimizer(...)` 返回 `MuonAdamW`，矩阵参数走 Muon，其余走 AdamW（`nanochat/gpt.py#GPT.setup_optimizer`）。
8. **GradScaler**：仅 fp16 时启用（bf16/fp32 不需要，`scripts/base_train.py:GradScaler`）。
9. **数据加载**：`tokenizing_distributed_data_loader_with_state_bos_bestfit` —— **边 tokenize 边打包**，BOS 对齐 + best-fit，100% 利用率、约 35% token 因裁剪丢弃（`nanochat/dataloader.py#tokenizing_distributed_data_loader_with_state_bos_bestfit`）。支持断点续训（`resume_state_dict`）。
10. **训练循环**（`scripts/base_train.py:Training loop`）：循环跑 `num_iterations + 1` 次，多出的最后一次用于末尾 eval/save。每步：grad_accum 次 fwd/bwd（**在 backward 后立刻 `next(train_loader)` 预取下一批**）→ 设 LR/momentum/wd 调度 → `optimizer.step()`。周期性做四件事：
    - **val bpb**（`scripts/base_train.py` 中 `evaluate_bpb` 调用点，`nanochat/loss_eval.py#evaluate_bpb`），包在 `disable_fp8` 里；
    - **CORE 指标**（`scripts/base_train.py` 中 `evaluate_core` 调用点，`scripts/base_eval.py#evaluate_core`），用 `orig_model`；
    - **采样**（`scripts/base_train.py` 中 7 个固定 prompt，温度 0，用 `Engine.generate_batch`）；
    - **存 checkpoint**（`scripts/base_train.py` 中 `save_checkpoint` 调用点）。
11. **checkpoint 结构**（`nanochat/checkpoint_manager.py#save_checkpoint`）：`model_<step>.pt`（rank0 存模型）、`optim_<step>_rank<rank>.pt`（每个 rank 存自己的优化器分片）、`meta_<step>.json`（元数据：step、val_bpb、model_config、user_config、dataloader_state_dict、loop_state 等）。

> **GC 优化**：第一步后 `gc.freeze()` + `gc.disable()`，每 5000 步手动 `gc.collect()`，避免周期性 GC 停顿（`scripts/base_train.py:Training loop` 末尾）。
>
> **MFU 口径**：`mfu = 100 * flops_per_sec / (gpu_peak_flops * ddp_world_size)`，而 `total_training_time` **只统计第 10 步之后**的耗时（前 10 步含编译与 cudnn 自动调优，不代表稳态）。

**关键产物**：`$NANOCHAT_BASE_DIR/base_checkpoints/d<depth>/` 下的模型 + 元数据。

## 阶段 4：监督微调（SFT）

**目的**：教会模型对话格式、多选题、数学工具调用。

入口 `scripts/chat_sft.py`，关键点：

1. **加载 base 模型**（`scripts/chat_sft.py:Load the model`）：`load_model("base", device, phase="train")`，从 `base_checkpoints` 构建。
2. **继承预训练超参**（`scripts/chat_sft.py:Inherit training hyperparameters`）：`max_seq_len` / `device_batch_size` / `total_batch_size` 从 checkpoint meta 继承，三个 LR 从 `user_config` 继承；显式传入的 CLI 参数会覆盖并打印 NOTE。
3. **优化器 weight_decay 置 0**：预训练末尾 cosine 调度已把 weight_decay 拉到 0，SFT 继续用 0（`scripts/chat_sft.py:Initialize the Optimizer`）。
4. **可选 warm-start 优化器**（`scripts/chat_sft.py` 中 `load_optimizer_state` 调用点，`--load-optimizer` 默认 1）：从 base checkpoint 加载动量缓冲；因为预训练 warmdown 把 LR 拉到 ~0，需要把 LR 重置回 SFT 的初始值。
5. **数据 mixture**（`scripts/chat_sft.py:SFT data mixture`）—— `TaskMixture` 把任务混在一起，**当前只有三项**：

   | 任务 | 切分 | 重复次数 |
   |------|------|----------|
   | `SmolTalk` | train（46 万行通用对话） | 1 |
   | `MMLU` | `auxiliary_train`（每 epoch 10 万行） | `--mmlu-epochs` 默认 3 |
   | `GSM8K` | train（每 epoch 8K 行） | `--gsm8k-epochs` 默认 4 |

   > **旧文档列的 `CustomJSON`（人格身份对话）、`SimpleSpelling`、`SpellingBee` 在当前仓库中不存在**——`tasks/` 下只有 `arc.py`、`common.py`、`gsm8k.py`、`humaneval.py`、`mmlu.py`、`smoltalk.py`。`runs/speedrun.sh` 也不再下载 `identity_conversations.jsonl`。
6. **对话打包**（`scripts/chat_sft.py#sft_data_generator_bos_bestfit`）：与预训练同款 best-fit，但**塞不下时用 BOS pad 填满而非裁剪**（`row.extend([bos_token] * remaining)`，pad 位 mask=0），因为对话不能裁断。padding 位与 mask=0 位在 target 上统一置 -1（`ignore_index`）。
7. **loss mask**：来自 `tokenizer.render_conversation`（`nanochat/tokenizer.py#RustBPETokenizer.render_conversation`）——只在 assistant 的回答内容与 python 工具调用上计算 loss；user 文本、BOS、特殊 token、python_output 一律 mask=0。
8. **停止条件**：数据驱动 —— 遍历完一整个 mixture（`consumed >= dataset_size`）或达到 `--num-iterations` 时停（`scripts/chat_sft.py#sft_data_generator_bos_bestfit`）。DDP 下用 `all_reduce(MAX)` 同步 `last_step` 避免挂死。
9. **LR 调度按 progress**：因为总步数事先未知，SFT 用 `progress`（0→1，由 `consumed / dataset_size` 或 `it / num_iterations` 得出）而不是绝对步数（`scripts/chat_sft.py#get_lr_multiplier`），且 `progress = max(progress, approx_progress)` 保证单调。
10. **训练中评估**：周期性算 **ChatCORE**（**5 个任务**的 centered mean，`--chatcore-every` 默认 200 步；同时额外记录 3 个 categorical 任务子集的 `chatcore_cat`）。生成式任务的样本数默认被 `--chatcore-max-sample` 限制到 24，靠 `--chatcore-max-cat` / `--chatcore-max-sample` 调（-1 = 不限）。

**关键产物**：`$NANOCHAT_BASE_DIR/chatsft_checkpoints/d<depth>/`。

## 阶段 5：强化学习（RL）

**目的**：在 GSM8K 上做 RL，提升数学推理与工具使用。nanochat 称之为「GRPO」，但实际更接近简化版 REINFORCE（`scripts/chat_rl.py` 模块 docstring）。

简化点（`scripts/chat_rl.py` docstring）：
1. 删除 trust region —— 无 KL 正则到参考模型；
2. on-policy —— 无需 PPO ratio+clip；
3. DAPO 风格的 **token 级**归一化（非 sequence 级）；
4. advantage 只用 `(r - mu)`，不做 z-score。

流程（`scripts/chat_rl.py` 的 `get_batch`）：
1. 取一道 GSM8K 题，`tokenizer.render_for_completion` 去掉末尾 assistant 回答、留下 `<|assistant_start|>` 作补全提示（`nanochat/tokenizer.py#RustBPETokenizer.render_for_completion`）。
2. 用 `Engine.generate_batch` 采样 `num_samples` 条回答（分批避免 OOM，每批换 seed：`hash((step, example_idx, sampling_step))`）。
3. 对每条回答调 `task.reward()`（GSM8K 里 reward = evaluate，`tasks/gsm8k.py#GSM8K.reward`）。
4. 把序列 pad 到等长，构造 inputs/targets，prompt 与工具输出位 target 设 -1。
5. advantage = reward - mean(reward)。
6. **PG 目标**：`logp = -model(inputs, targets, loss_reduction='none')`，`pg_obj = (logp * advantage).sum()`，再除以 `num_valid * num_passes * examples_per_rank`（`num_valid = (targets >= 0).sum()`），最小化 `-pg_obj`。
7. 评估：GSM8K **pass@k**（k=1..device_batch_size）。
8. LR 先乘 `--init-lr-frac`（默认 0.05）并写回 `initial_lr`，然后 `lrm = 1.0 - it / num_steps` **线性递减到 0**（没有 warmup、也没有 warmdown 比例）。
9. **不保存优化器状态**（`save_checkpoint` 的 optimizer_data 传 `None`），所以 RL 无法从 checkpoint 续训。

> **与 SFT 的对比**：SFT 的 `--init-lr-frac` 默认是 **0.8**（从 base 的 80% 开始），RL 是 **0.05**（几乎从零附近重新爬，避免破坏 SFT 学到的格式）。两者都会把乘完的结果写回 `initial_lr`，之后调度器只乘 multiplier。

**关键产物**：`$NANOCHAT_BASE_DIR/chatrl_checkpoints/d<depth>/`（RL 目前较实验性）。

## 阶段 6：评估、推理基准与对话

### Base 模型评估 `scripts/base_eval.py`

三种模式（默认全跑）：
- **`core`**：CORE 指标，ICL 任务准确率（multiple_choice / schema / language_modeling 三类，`nanochat/core_eval.py`），数据来自下载的 `eval_bundle.zip`（`scripts/base_eval.py#place_eval_bundle`）。
- **`bpb`**：train/val 上的 bits-per-byte（`nanochat/loss_eval.py#evaluate_bpb`），用 `token_bytes` 把 loss 归一化为词表无关指标。
- **`sample`**：条件/无条件采样。

CORE 计算（`scripts/base_eval.py#evaluate_core`）：每个任务用 `(accuracy - 0.01*random_baseline) / (1 - 0.01*random_baseline)` 做 centered 归一化（**注意 random baseline 来自 csv，是百分数，所以乘了 0.01**），再取均值。

> 当前 `base_eval.py` **不支持评估外部 HuggingFace 模型**——旧文档提到的 `--hf-path` / `ModelWrapper` / `load_hf_model` 已随 HF tokenizer 一起删除。

### Chat 模型评估 `scripts/chat_eval.py`

**5 个任务**（`scripts/chat_eval.py#run_chat_eval` 与 `__main__` 段），分两类：
- **categorical**（`run_categorical_eval`）：ARC-Easy / ARC-Challenge / MMLU。无需采样，批量 forward 取答案字母位的 logits argmax（只在可选字母上比）。
- **generative**（`run_generative_eval`）：GSM8K / HumanEval。逐题采样再判分（HumanEval 用 `execution.py` 子进程执行）。

**ChatCORE** = 5 个任务 centered accuracy 的均值（baseline：多选题 0.25，生成题 0.0）。

### 推理基准 `scripts/infer_bench.py`

这是**独立于「智能指标」的成本评测**：CORE 高不代表推理便宜。它扫 batch size，测量：

- **Prefill**：整段 prompt 并行处理，大 matmul、compute-bound，用 **MFU** 衡量；
- **Decode**：每步只生成 1 token，却要重读全部权重 + KV cache，**memory-bandwidth-bound**，用 **MBU**（Model Bandwidth Utilization）衡量；
- **TTFT / TPOT / tok/s / peak VRAM**；
- **静态卡片**：架构隐含的成本下限——`model.kv_bytes_per_token()`、`model.kv_read_bytes(ctx)`、理论 decode 上限 `peak_bw / (权重字节 + kv_read)`、VRAM 能容纳多少 full-context 行。

末行输出一个完整 JSON，可被脚本消费。详见 [05-推理与评测](05-推理与评测.md) §5。

### 对话 `scripts/chat_cli.py`

- 单 GPU 交互式 REPL（唯一的对话入口）。维护 `conversation_tokens`（BOS 起始），每轮把用户输入包进 `<|user_start|>...<|user_end|>` 后追加 `<|assistant_start|>`，交给 `engine.generate` 流式输出。
- 支持 `-p "问题"` 一次性问答（答完即退出）、`clear` 清空上下文、`quit`/`exit` 退出。
- 默认 `temperature=0.6`、`top_k=50`、`max_tokens=256`。
- **如果生成因 max_tokens 截断**（最后一个 token 不是 `<|assistant_end|>`），代码会手动补上 `<|assistant_end|>` 再追加进历史，保证上下文格式完整。
- 生成逻辑在推理引擎 `nanochat/engine.py`，详见 [05-推理与评测](05-推理与评测.md)。

## 贯穿全流程的「对话渲染」

所有 chat 阶段都依赖 `tokenizer.render_conversation`（`nanochat/tokenizer.py#RustBPETokenizer.render_conversation`）把一个 `{messages: [...]}` 结构渲染成 token id + mask：

```
<|bos|> <|user_start|> 用户文本 <|user_end|> <|assistant_start|> 回答 <|assistant_end|> ...
```

- mask=1 的位置才会被训练：assistant 的文本与 python 工具调用内容；user/bos/特殊 token/python_output 一律 mask=0。
- system 消息会被「缝合」进第一条 user 消息（`content + "\n\n" + user_content`）。
- 渲染时用 `assert message["role"] == must_be_from` 强制 user/assistant 严格交替，防止数据格式踩坑。
- 末尾按 `max_tokens` 截断（默认 2048）以防 OOM。
- `render_for_completion`（`nanochat/tokenizer.py#RustBPETokenizer.render_for_completion`）用于 RL/生成式评测：弹掉最后一条 assistant 消息、追加 `<|assistant_start|>` 作为补全提示，且**不返回 mask**（RL 的 mask 来自推理引擎的 forced/sampled 标记）。
- `visualize_tokenization`（`nanochat/tokenizer.py#RustBPETokenizer.visualize_tokenization`）用红/绿标出 mask 位置，调试渲染问题很好用。

## 指标怎么记录

**没有报告模块**。各阶段脚本只做两件事：

1. `print0(...)` 输出到 stdout（rank 0）；
2. `wandb_run.log({...})`（`--run=dummy` 时是 `DummyWandb`，空操作）。

想要留档就开 wandb（`WANDB_RUN=xxx bash runs/speedrun.sh`）或自己重定向 stdout。`base_train` 与 `chat_sft` 都在循环末尾打印总训练时间与最小 val_bpb。
