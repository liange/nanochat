# 02 - 核心流程

本章按数据流自上而下走一遍 nanochat 的端到端链路：从原始文本到一个能对话的模型。每个阶段都会指出**输入是什么、输出是什么、由谁负责、关键源码在哪**。

```
┌────────────┐   ┌──────────┐   ┌──────────┐   ┌──────┐   ┌───────┐   ┌──────────┐
│ 1. 数据准备 │──▶│ 2. Token │──▶│ 3. 预训练 │──▶│ 4.SFT│──▶│ 5.RL │──▶│ 6.评估/对话│
│  (parquet) │   │  -izer  │   │  (base)  │   │      │   │      │   │           │
└────────────┘   └──────────┘   └──────────┘   └──────┘   └───────┘   └──────────┘
   dataset.py       tok_train       base_train    chat_sft   chat_rl   base_eval
                     tok_eval                       chat_eval           chat_eval
                                                                 chat_cli / chat_web
```

## 阶段 1：数据准备

**目的**：把预训练语料以 parquet 分片形式下载到本地。

- 数据集是 **ClimbMix-400B**（HuggingFace `karpathy/climbmix-400b-shuffle`），共 6542 个分片（`nanochat/dataset.py:23`）。
- 入口 `python -m nanochat.dataset -n 170`：`-n` 指定下载多少个**训练分片**，最后一个分片固定作为验证集（`nanochat/dataset.py:147`）。
- 下载支持多进程并发、断点续传（跳过已存在文件）、指数退避重试（`nanochat/dataset.py:84`）。
- 落盘位置：`$NANOCHAT_BASE_DIR/base_data_climbmix/`（`nanochat/dataset.py:27`）。
- 遍历工具 `list_parquet_files` / `parquets_iter_batched`（`nanochat/dataset.py:32 / :67`）供 dataloader 和 tokenizer 复用；train/val 划分规则：除最后一个分片外都是 train（`nanochat/dataset.py:38`）。

> 兼容历史：若找不到 ClimbMix 目录，会回退到旧的 FinewebEdu-100B 并打印升级提示（`nanochat/dataset.py:38`）。

## 阶段 2：Tokenizer 训练

**目的**：训练一个 GPT-4 风格的 BPE tokenizer，词表大小默认 32768（2^15）。

- 入口 `scripts/tok_train.py`，用前 ~2B 字符训练（`scripts/tok_train.py:17`）。
- 实现是 **rustbpe 训练 + tiktoken 推理** 的组合（`nanochat/tokenizer.py:163`）：
  - 训练时 `rustbpe.Tokenizer().train_from_iterator(...)`（`nanochat/tokenizer.py:177`）；
  - 训练完构造一个 `tiktoken.Encoding` 供高效推理（`nanochat/tokenizer.py:184`）。
- 分词正则 `SPLIT_PATTERN`（`nanochat/tokenizer.py:30`）是 GPT-4 风格，但把数字位数从 `\p{N}{1,3}` 改成 `\p{N}{1,2}`，以免在小词表下浪费 token。
- 特殊 token 在 `SPECIAL_TOKENS`（`nanochat/tokenizer.py:13`）定义，用于对话格式与工具调用：
  - `<|bos|>` 文档/序列起始；`<|user_start|>/<|user_end|>`、`<|assistant_start|>/<|assistant_end|>` 包裹对话；
  - `<|python_start|>/<|python_end|>` 触发计算器工具，`<|output_start|>/<|output_end|>` 包裹工具输出。
- **副产物 `token_bytes.pt`**：缓存每个 token id 对应的 UTF-8 字节数（特殊 token 记 0），供 bpb 指标使用（`scripts/tok_train.py:76`）。
- 评估 `scripts/tok_eval.py` 报告压缩率。
- 加载入口 `nanochat/tokenizer.py:390` 的 `get_tokenizer()`，默认读 `$NANOCHAT_BASE_DIR/tokenizer/`。

## 阶段 3：预训练（Pretrain）

**目的**：在 ClimbMix 上训练 base 模型，达到 GPT-2 级能力（CORE > 0.256525）。

入口 `scripts/base_train.py`，关键流程：

1. **初始化**（`scripts/base_train.py:84`）：`compute_init` 做 DDP/精度/seed 设置；rank 0 接 wandb，其余用 `DummyWandb`。
2. **构建模型（meta device）**（`scripts/base_train.py:129`）：先在 meta device 上建模型（只有形状/dtype，无数据），再 `to_empty` 分配显存、`init_weights` 初始化权重（`nanochat/gpt.py:202`）。这样避免重复分配内存。
3. **可选 FP8**（`scripts/base_train.py:168`）：把符合条件的 `Linear` 转成 `Float8Linear`（需 H100+，默认 tensorwise scaling）。
4. **torch.compile**（`scripts/base_train.py:246`）：`dynamic=False`（输入形状固定）。
5. **超参推导**（`scripts/base_train.py:263`）：根据 scaling laws 自动算出训练 token 数、batch size、LR 缩放、weight decay（详见 [04-模型与训练机制](04-模型与训练机制.md)）。
6. **优化器**（`scripts/base_train.py:308`）：`model.setup_optimizer(...)` 返回 `MuonAdamW` / `DistMuonAdamW`，矩阵参数走 Muon，其余走 AdamW。
7. **数据加载**（`scripts/base_train.py:331`）：`tokenizing_distributed_data_loader_with_state_bos_bestfit` —— **边 tokenize 边打包**，BOS 对齐 + best-fit 裁剪，100% 利用率（`nanochat/dataloader.py:74`）。支持断点续训（`resume_state_dict`）。
8. **训练循环**（`scripts/base_train.py:416`）：每步梯度累积 → 设 LR/momentum/wd 调度 → `optimizer.step()`。周期性做：
   - **val bpb**（`scripts/base_train.py:421`，`nanochat/loss_eval.py`）；
   - **CORE 指标**（`scripts/base_train.py:442`，`scripts/base_eval.py:107`）；
   - **采样**（`scripts/base_train.py:457`，用 `Engine`）；
   - **存 checkpoint**（`scripts/base_train.py:477`）。
9. **checkpoint 结构**（`nanochat/checkpoint_manager.py:42`）：`model_<step>.pt`（rank0 存模型）、`optim_<step>_rank<rank>.pt`（每个 rank 存自己的优化器分片）、`meta_<step>.json`（元数据：step、val_bpb、model_config、user_config、dataloader_state_dict、loop_state 等）。

> GC 优化：第一步后 `gc.freeze()` + `gc.disable()`，每 5000 步手动 `gc.collect()`，避免周期性 GC 停顿（`scripts/base_train.py:589`）。

**关键产物**：`$NANOCHAT_BASE_DIR/base_checkpoints/d<depth>/` 下的模型 + 元数据。

## 阶段 4：监督微调（SFT）

**目的**：教会模型对话格式、多选题、数学工具调用、拼写等能力。

入口 `scripts/chat_sft.py`，关键点：

1. **加载 base 模型**（`scripts/chat_sft.py:96`）：`load_model("base", device, phase="train")`，从 `base_checkpoints` 构建。
2. **继承预训练超参**（`scripts/chat_sft.py:98`）：batch size / seq len / LR 等默认从预训练 checkpoint 的 meta 继承，可用 CLI 覆盖。
3. **可选 warm-start 优化器**（`scripts/chat_sft.py:141`）：从 base checkpoint 加载优化器动量（LR 会被预训练 warmdown 拉到 ~0，需重置回 SFT 的 LR）。
4. **数据 mixture**（`scripts/chat_sft.py:165`）—— `TaskMixture` 把多个任务混在一起（重复传入即过采样）：
   - `SmolTalk`（46 万通用对话）、`CustomJSON`（人格身份对话 ×2 epoch）、`MMLU`（×3 epoch）、`GSM8K`（×4 epoch）、`SimpleSpelling`（20 万）、`SpellingBee`（8 万）。
5. **对话打包**（`scripts/chat_sft.py:187`）：与预训练类似，但用 **best-fit padding**（塞不下就 pad 而非裁剪，pad 位 target 设 -1 忽略）。loss mask 来自 `tokenizer.render_conversation`：只在 assistant 的回答内容上计算 loss（`nanochat/tokenizer.py:266`）。
6. **停止条件**：数据驱动 —— 当遍历完一整个 mixture（`consumed >= dataset_size`）或达到 `--num-iterations` 时停（`scripts/chat_sft.py:283`）。DDP 下用 all_reduce 同步 `last_step` 避免挂死（`scripts/chat_sft.py:341`）。
7. **训练中评估**：周期性算 **ChatCORE**（6 个任务的 centered mean，`scripts/chat_sft.py:366`）。

**关键产物**：`$NANOCHAT_BASE_DIR/chatsft_checkpoints/d<depth>/`。

## 阶段 5：强化学习（RL）

**目的**：在 GSM8K 上做 RL，提升数学推理与工具使用。nanochat 称之为「GRPO」，但实际更接近简化版 REINFORCE（`scripts/chat_rl.py:1` 的注释）。

简化点（`scripts/chat_rl.py:5`）：
1. 删除 trust region —— 无 KL 正则到参考模型；
2. on-policy —— 无需 PPO ratio+clip；
3. DAPO 风格的 **token 级**归一化（非 sequence 级）；
4. advantage 只用 `(r - mu)`，不做 z-score。

流程（`scripts/chat_rl.py:85` 的 `get_batch`）：
1. 取一道 GSM8K 题，`tokenizer.render_for_completion` 去掉末尾 assistant 回答、留下 `<|assistant_start|>` 作补全提示（`nanochat/tokenizer.py:367`）。
2. 用 `Engine.generate_batch` 采样 `num_samples` 条回答（分批避免 OOM，每批换 seed）。
3. 对每条回答调 `task.reward()`（GSM8K 里 reward = evaluate，`tasks/gsm8k.py:110`）。
4. 把序列 pad 到等长，构造 inputs/targets，prompt 与工具输出位 target 设 -1（`scripts/chat_rl.py:138`）。
5. advantage = reward - mean(reward)（`scripts/chat_rl.py:143`）。
6. **PG 目标**（`scripts/chat_rl.py:264`）：`logp = -model(inputs, targets, loss_reduction='none')`，`pg_obj = (logp * advantage).sum() / num_valid`，最小化 `-pg_obj`。
7. 评估：GSM8K **pass@k**（k=1..device_batch_size，`scripts/chat_rl.py:225`）。
8. LR 线性递减到 0（`scripts/chat_rl.py:210`）；不保存优化器状态。

**关键产物**：`$NANOCHAT_BASE_DIR/chatrl_checkpoints/d<depth>/`（RL 目前较实验性）。

## 阶段 6：评估与对话

### Base 模型评估 `scripts/base_eval.py`

三种模式（默认全跑，`scripts/base_eval.py:180`）：
- **`core`**：CORE 指标，ICL 任务准确率（multiple_choice / schema / language_modeling 三类，`nanochat/core_eval.py`），数据来自下载的 `eval_bundle.zip`（`scripts/base_eval.py:92`）。
- **`bpb`**：train/val 上的 bits-per-byte（`nanochat/loss_eval.py`），用 `token_bytes` 把 loss 归一化为词表无关指标。
- **`sample`**：条件/无条件采样。

CORE 计算（`scripts/base_eval.py:159`）：每个任务用 `(accuracy - random_baseline) / (1 - random_baseline)` 做 centered 归一化，再取均值（`nanochat/core_eval.py` 与 `scripts/base_eval.py:162`）。

> 也支持评估 HuggingFace 模型（如 `--hf-path openai-community/gpt2`），用 `ModelWrapper` 适配接口（`scripts/base_eval.py:45`）。

### Chat 模型评估 `scripts/chat_eval.py`

6 个任务（`scripts/chat_eval.py:204`），分两类：
- **categorical**（`run_categorical_eval`，`scripts/chat_eval.py:88`）：ARC-Easy / ARC-Challenge / MMLU。无需采样，批量 forward 取答案字母位的 logits argmax（只在可选字母上比）。
- **generative**（`run_generative_eval`，`scripts/chat_eval.py:29`）：GSM8K / HumanEval / SpellingBee。逐题采样再判分（HumanEval 用 `execution.py` 沙箱执行）。

**ChatCORE** = 6 个任务 centered accuracy 的均值（`scripts/chat_eval.py:238`）。

### 对话 `scripts/chat_cli.py` / `scripts/chat_web.py`

- `chat_cli.py`：单 GPU 交互式 REPL。维护 `conversation_tokens`（BOS 起始），每轮把用户输入包进 `<|user_start|>...<|user_end|>` 后追加 `<|assistant_start|>`，交给 `engine.generate` 流式输出（`scripts/chat_cli.py:45`）。支持 `-p "问题"` 一次性问答。
- `chat_web.py`：ChatGPT 风格 WebUI，前端是 `nanochat/ui.html`。
- 真正的生成逻辑在推理引擎 `nanochat/engine.py`，详见 [05-推理与评测](05-推理与评测.md)。

## 贯穿全流程的「对话渲染」

所有 chat 阶段都依赖 `tokenizer.render_conversation`（`nanochat/tokenizer.py:266`）把一个 `{messages: [...]}` 结构渲染成 token id + mask：

```
<|bos|> <|user_start|> 用户文本 <|user_end|> <|assistant_start|> 回答 <|assistant_end|> ...
```

- mask=1 的位置才会被训练：assistant 的文本与 python 工具调用内容；user/bos/特殊 token/python_output 一律 mask=0（`nanochat/tokenizer.py:302`）。
- system 消息会被「缝合」进第一条 user 消息（`nanochat/tokenizer.py:283`）。
- `render_for_completion`（`nanochat/tokenizer.py:367`）用于 RL/生成式评测：弹掉最后一条 assistant 消息、追加 `<|assistant_start|>` 作为补全提示。

## 报告生成

每个阶段的脚本结尾都会 `get_report().log(section, data)`（`nanochat/report.py:400`）把关键指标写到 `$NANOCHAT_BASE_DIR/report/<section>.md`。`nanochat.report generate`（`nanochat/report.py:415`）把它们拼成最终 `report.md`：header（git/硬件/成本/代码行数）+ 各阶段 + summary 指标表 + 总耗时（`nanochat/report.py:279`）。
